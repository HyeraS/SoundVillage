# 참여자 브라우저 이동 정책

## 최종 동작

- 일반 참여자는 페이지를 새로 열거나 새로고침할 때마다 참여자 ID와 그룹을 다시 입력한다.
- 같은 ID로 새 브라우저에서 로그인하면 가장 최근에 로그인한 브라우저가 활성 브라우저가 된다.
- 기존 브라우저의 서버 권한은 DB 연결이 교체되는 즉시 사라진다.
- 진행 중이거나 완료된 연구 세션의 소유권도 새 인증 사용자로 이동하여 이벤트 기록과 실험 완료 상태를 이어간다.
- 기존 브라우저 화면은 포커스 복귀 시 또는 최대 약 4초 뒤 로그인 화면으로 돌아가며, 다른 브라우저로 이동되었다는 안내를 표시한다.
- `MASTER`는 비밀번호 로그인을, `USER1`은 공유 시연 계정을 계속 사용하므로 일반 참여자 이동 대상에서 제외한다.

## 배포 순서

1. Supabase에 `scripts/security/016_participant_session_takeover.sql`을 적용한다.
2. 애플리케이션을 배포한다.
3. 서로 다른 두 브라우저에서 동일한 테스트 참여자 ID로 차례대로 로그인한다.
4. 두 번째 브라우저는 정상 입장하고 첫 번째 브라우저는 로그인 화면으로 돌아가는지 확인한다.
5. 첫 번째 브라우저의 이전 토큰으로 보호된 RPC를 호출했을 때 참여자 데이터 접근이 거부되는지 확인한다.

앱을 먼저 배포해도 기존 DB에서는 `participant_claimed` 안내가 표시되어 안전하게 실패하지만, 실제 브라우저 이동 기능은 016 migration 적용 후 활성화된다.

## 보안상 주의점

현재 일반 참여자 인증 정보는 `참여자 ID + 배정 그룹`이다. 따라서 이 두 값을 아는 사람은 해당 참여자 세션을 자기 브라우저로 이동시킬 수 있다. 외부 공개 실험으로 운영할 경우 참여자별 접속 코드를 추가하는 것이 권장된다.
