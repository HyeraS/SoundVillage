## 1. 레퍼런스 리서치

### 1.1 Animal Crossing: New Horizons — 방 꾸미기

#### 핵심 해석

Animal Crossing의 방은 엄밀한 의미의 고정 아이소메트릭 투영이라기보다, 바닥과 두 벽을 동시에 보여 주는 **회전 가능한 3/4 다이어라마 뷰**에 가깝다. 공간은 입체적으로 보이지만 실제 편집은 그리드 스냅과 배치 면 분리로 단순하다. 즉, “보기에는 풍부하고 조작 규칙은 예측 가능하게” 만든 것이 핵심이다.

#### 구체적 화면/인터랙션 패턴

1. **바닥과 두 벽이 한 화면에 들어오는 높은 3/4 시점**  
   방의 뒤쪽 벽과 옆 벽, 바닥을 함께 보여 주어 가구의 앞뒤 관계를 읽게 한다. 원근은 존재하므로 정통 45도 아이소메트릭보다 작은 디오라마 상자를 들여다보는 인상이다. 방을 꾸미는 동안에도 완성 장면을 크게 가리지 않는다.

2. **방을 유지한 채 옆에서 열리는 인벤토리 패널**  
   공개 스크린샷에서는 꾸며지는 방이 화면 대부분을 유지하고, 가구 선택 패널이 한쪽에 겹쳐 열린다. 선택 중에도 가구가 실제 방에 어울리는지 계속 비교할 수 있다. 패널에는 아이템 썸네일, 현재 아이템 이름, 정렬·변형·닫기·선택 버튼 힌트가 함께 보인다.

3. **아이콘 그리드와 카테고리로 탐색 비용을 낮춘 보관함**  
   저장 공간은 의자·침대·조명·벽지·바닥·러그처럼 시각 썸네일을 촘촘한 그리드로 보여 준다. `Everything` 같은 범주와 정렬 기능, 사용량 표시가 있어 보유품이 많아져도 탐색 구조가 유지된다. 텍스트 목록보다 “모양을 보고 고르는” 흐름이다.

4. **선택 → 방에 생성 → 이동/회전 → 완료의 직접 조작 흐름**  
   인벤토리에서 아이템을 선택하면 방 안에 생성되고, 커서로 잡아 그리드 위를 이동한다. 짧게 누르면 회전, 길게 잡으면 이동, 범위 선택으로 여러 가구를 함께 옮길 수 있다. 삭제한 물건은 사라지는 대신 보관함으로 돌아가므로 실험 비용이 낮다.

5. **바닥·벽·천장을 별도 편집 면으로 분리**  
   일반 가구, 벽걸이, 천장 장식은 같은 좌표계에 억지로 섞지 않는다. `+` 입력으로 모드를 바꾸며, 벽 모드에서는 정면에 가까운 벽 편집 뷰를 사용한다. 따라서 “벽에 붙일 수 있는가”는 육안 추측이 아니라 아이템 종류와 현재 모드로 명확해진다.

6. **그리드 스냅과 점유 면적으로 충돌을 예측 가능하게 처리**  
   가구는 자유 픽셀 좌표가 아니라 정해진 그리드 위치에 맞춰지고, 크기에 따라 여러 칸을 점유한다. 벽 가까이 밀어 정렬할 수 있지만 일반 가구가 자동으로 벽걸이가 되지는 않는다. 벽걸이 아이템만 벽 좌표를 사용한다는 분리가 중요하다.

7. **러그는 가구 아래에 깔리는 ‘구역 레이어’**  
   러그는 작은/중간/큰 크기로 제공되고 가구 아래에 둘 수 있지만 러그끼리는 겹치지 않는다. 하나의 큰 방 안에서 소파+테이블은 거실 존, 책장+의자는 독서 존처럼 기능별 섬을 만든다. 바닥재가 방 전체 분위기를 정한다면 러그는 국소 구역을 정의한다.

8. **색과 소재를 세트로 묶어 초보자도 통일감을 만들게 함**  
   자연 목재, 파스텔 침실, 네온 라운지처럼 벽지·바닥·가구가 테마 세트로 연결된다. 밝은 벽과 어두운 바닥처럼 큰 면의 대비가 먼저 보이고, 작은 소품이 포인트 컬러를 반복한다. 아이템 하나보다 “같이 놓기 좋은 묶음”을 제안하는 방식이다.

9. **조명이 편집 항목이면서 완성 장면의 분위기 피드백 역할**  
   기본 방 조명을 켜고 끌 수 있고, 확장 기능에서는 밝기·색조 조정과 천장/스탠드/벽 조명을 함께 사용한다. 따뜻한 저채도 조명은 목재와 패브릭을 포근하게 보이게 하고, 컬러 조명은 테마를 즉시 바꾼다. 편집 UI를 닫지 않아도 결과가 방 전체에 바로 반영된다.

#### Sound Village에 가져올 원칙

- 렌더링은 3/4 다이어라마처럼 보이게 하되 데이터는 현재와 같은 명시적 그리드 좌표를 유지한다.
- `바닥 가구 / 벽 장식 / 러그`를 필터와 배치 규칙 모두에서 분리한다.
- 선택한 물건의 유효 셀, 점유 셀, 벽 인접 가능 여부를 배치 전에 하이라이트한다.
- 인벤토리를 열어도 방과 코인 잔액이 가려지지 않게 한다.
- 러그는 충돌 가구가 아니라 가구 아래에 놓이는 별도 구역 레이어로 설계한다.

### 1.2 SumOne — 반려몽 꾸미기 상점

#### 핵심 해석

SumOne의 강점은 정교한 자유 배치보다 **공동 재화 → 테마 수집 → 마스코트의 공간 변화**를 매우 짧게 연결하는 데 있다. 상점은 일반 커머스처럼 보이지 않고, 반려몽을 돌보며 공동 공간을 채우는 놀이의 일부로 보인다.

#### 구체적 화면/인터랙션 패턴

1. **상점 상단에서 조약돌 잔액과 획득 경로를 함께 노출**  
   공개 상점 스크린샷은 상단에 현재 조약돌 잔액을 표시하고, 바로 아래에 광고 시청 등으로 조약돌을 얻는 뉴스/충전 영역을 둔다. “얼마가 남았나”와 “부족하면 어디서 얻나”를 한 화면에서 해결한다. 공식 FAQ도 조약돌 아이콘을 통한 Shop 진입과 일일 조약돌 줍기를 안내한다.

2. **재화를 숫자가 아니라 세계관 소품으로 표현**  
   조약돌은 연인이 함께 모으고 함께 쓰는 공동 재산이다. 통화 아이콘도 동전이나 지갑보다 작은 돌 형태를 사용해 마스코트 세계관과 연결한다. 숫자만 갱신하는 대신 획득 시 돌이 굴러 들어오거나 주머니가 차는 식의 피드백을 붙이기 좋은 구조다.

3. **상점 상품을 용도별 섹션으로 나눔**  
   공개 화면에는 `Item` 섹션과 `Interior Object` 섹션이 분리되어 있다. 메모, 반려몽 일기, 이름 등록 같은 기능성 아이템과 방을 바꾸는 인테리어 오브제가 같은 카드 체계를 쓰되 다른 묶음으로 진열된다.

4. **테마 카드에 완성도와 대표 방 이미지를 함께 표시**  
   `Romantic Lilac`, `Secret Garden`, `Cozy Room`, `Bakery House`, `Modern City Life` 같은 테마가 카드/행 단위로 보이고, 일부에는 `6/12`, `5/12`, `3/12`처럼 수집 진행도가 붙는다. 개별 상품 구매가 곧 테마 완성이라는 장기 목표로 연결된다.

5. **구매 이후 ‘바로 배치하기’로 흐름을 이어 줌**  
   공식 한국어 FAQ가 `Shop → 인테리어 오브제 → 구매 → 바로 배치하기` 순서를 명시한다. 구매 성공을 토스트로 끝내지 않고, 방에서 즉시 변화를 확인하게 만드는 전환이다. 구매한 오브제는 환불이 불가능하므로 가격·잔액·구매 후 잔액을 확인 단계에서 분명히 보여 줄 필요가 있다.

6. **배치 위치를 제한하고 마지막에 체크로 확정**  
   공식 다국어 FAQ에 따르면 Interior에서는 놓고 싶은 영역을 먼저 누르고, 그 위치에 보유한 오브제를 선택한 뒤 우측 상단 체크 표시로 확정한다. 각 오브제는 지정된 위치에만 놓을 수 있다. 자유도는 낮지만 실패/충돌 메시지가 거의 필요 없고 모바일 터치에 적합하다.

7. **파스텔 배경과 둥근 카드가 상업성을 부드럽게 만듦**  
   공개 앱 화면은 크림·피치·라일락·민트 계열의 저채도 색, 큰 라운드, 얇거나 거의 없는 테두리, 작은 그림자, 여백이 넓은 카드를 반복한다. 가격이 강하게 튀기보다 상품 일러스트와 테마 이름이 먼저 읽히는 구성이다.

8. **마스코트가 꾸미기의 목적과 결과를 동시에 보여 줌**  
   반려몽은 홈과 꾸며진 방의 중앙에 크게 남아 있고, 소파·식물 같은 오브제가 그 주변을 채운다. 마스코트의 성장과 방의 변화가 같은 화면에 있어 “누구를 위해 꾸미는가”가 즉시 이해된다. 별도 도움말보다 캐릭터의 말풍선으로 부족한 재화, 새 아이템, 방문 가능 상태를 안내하기 좋다.

9. **테마 완성 보상을 카드 안에서 예고**  
   공식 FAQ는 테마의 오브제를 모을 때마다 완성 게이지가 차고, 마지막 `???` 선물 상자가 반짝인다고 설명한다. 잠긴 보상을 완전히 숨기지 않고 실루엣/선물상자로 미리 보여 주어 다음 구매 동기를 만든다.

#### 구매 확인 UI에 대한 확인 범위

공개 자료에서 현재 버전의 정확한 구매 확인 모달 모양까지는 신뢰성 있게 확인하지 못했다. 확인된 사실은 `가격/조약돌로 구매`, `환불 불가`, `구매 후 바로 배치`, `Interior에서 체크로 배치 확정`이다. 따라서 Sound Village에서는 이를 바탕으로 **상품 카드 선택 → 하단 확인 시트(현재 잔액/가격/구매 후 잔액) → 구매 성공 애니메이션 → 바로 배치** 흐름을 새로 설계하는 것이 안전하다. 이 확인 시트 자체를 SumOne의 실제 화면이라고 간주하지 않는다.

#### Sound Village에 가져올 원칙

- 코인 잔액을 상점·인벤토리·방 화면의 같은 위치에 고정한다.
- 상품은 큰 일러스트 카드로 보여 주고 `가격 / 보유 수 / 배치 중 수`를 구분한다.
- 테마 컬렉션과 `n/전체` 완성도를 노출해 보상 획득을 장기 목표로 만든다.
- 구매 전후 잔액을 확인시키고, 성공 직후 `바로 배치`를 1차 행동으로 제공한다.
- Sound Village의 마스코트가 새 보상, 코인 부족, 집 공개 가능 상태를 말풍선으로 안내한다.

## 2. Sound Village 디자인 방향

### 2.1 레퍼런스 역할 분담

| 영역 | 주 레퍼런스 | 적용할 것 | 적용하지 않을 것 |
|---|---|---|---|
| 상점·인벤토리·재화 | SumOne | 파스텔 카드, 코인 상시 노출, 테마 진행도, 마스코트 안내, 구매 후 바로 배치 | 오브제마다 단 하나의 고정 위치만 허용하는 낮은 자유도 |
| 방 배치 | Animal Crossing | 3/4 공간감, 그리드 스냅, 바닥/벽/러그 레이어, 배치 미리보기, 회전 | 콘솔 버튼 체계와 복잡한 카메라 조작의 직접 복제 |
| 친구 방문·초대 진입점 | 두 레퍼런스의 공통 원칙을 확장 | 꾸며진 집을 관계의 허브로 사용, 집 공개 상태와 친구 아바타 노출 | 이번 집꾸미기 1차 구현에서 실시간 멀티플레이까지 한 번에 포함 |

권장 결합 방식은 **“SumOne 껍질 안의 Animal Crossing 편집기”**다. 기본 상태에서는 마스코트와 코인, 상점/인벤토리 카드가 친근하게 보이고, `꾸미기`를 누르면 방이 중심이 되며 유효 배치 영역과 레이어 도구가 나타난다.

### 2.2 권장 화면 구조

1. **상단 고정 HUD**: 뒤로가기, 집 이름/마을, 코인 잔액, 초대 버튼.
2. **중앙 방 캔버스**: 마스코트가 생활하는 3/4 방. 편집 중에만 배치 그리드와 유효 셀을 표시.
3. **하단 도크**: `상점 / 내 아이템 / 꾸미기 / 친구`를 큰 아이콘과 짧은 라벨로 제공.
4. **하단 시트**: 상점·인벤토리를 카드 그리드로 열되 방의 상단 절반은 계속 보이게 유지.
5. **상태 배지**: `아직 비공개 → 살만해지는 중 → 친구 초대 가능`을 집 완성도와 연결. 정확한 공개 기준과 보상 개수는 별도 게임 밸런스 결정이 필요하다.

### 2.3 디자인 토큰

#### 색상 팔레트 — 5색

| 토큰 | 값 | 용도 |
|---|---:|---|
| `cream` | `#F7F0E3` | 전체 배경, 포근한 종이 톤 |
| `surface` | `#FFFDF8` | 카드, 하단 시트, 말풍선 |
| `peach` | `#FF9F86` | 주요 CTA, 구매 성공, 초대 강조 |
| `mint` | `#91CDB2` | 선택 상태, 배치 가능 셀, 진행 완료 |
| `cocoa` | `#3A2A1E` | 본문, 아이콘, 대비가 필요한 테두리 |

보조 상태색은 위 팔레트에서 파생한다. 예: 비활성은 `cocoa`의 낮은 투명도, 경고는 `peach`를 더 진하게, 그림자는 `cocoa / 12%`. 새로운 원색을 계속 추가하지 않는다. 현재 전역의 베이지·브라운 계열과 충돌하지 않고, 피치와 민트만 집꾸미기 고유 포인트가 된다.

#### 타이포그래피

- 기본 폰트는 현재 프로젝트의 `Nunito`를 유지한다. 둥근 산세리프라 캐주얼 게임 UI와 숫자 HUD에 모두 맞는다.
- 화면 제목: 24–28px, 800 weight, 짧고 친근한 문장형.
- 카드 이름/잔액: 15–17px, 700–800 weight. 가격 숫자는 아이콘과 한 덩어리로 보이게 한다.
- 도움말/상태: 12–13px, 600 weight. 명령형보다 마스코트의 말투로 안내한다.
- 장식용 손글씨 폰트는 사용하지 않는다. 한글 가독성과 로딩 비용에 비해 얻는 이점이 작다.

#### 카드와 버튼

- 카드 반경: 18px. 선택 카드에는 민트 2px 링과 아주 작은 상승 효과를 준다.
- 시트/큰 패널 반경: 상단 모서리 24px.
- 주 버튼: 높이 48–52px, 캡슐형 또는 16px 라운드, 피치 배경+짙은 코코아 텍스트.
- 보조 버튼: 크림/화이트 표면+코코아 12% 테두리.
- 그림자: `0 8px 24px rgba(58, 42, 30, 0.12)` 수준의 넓고 약한 그림자.
- 터치 영역: 아이콘 버튼도 최소 44×44px. 색만으로 선택/잠금/구매 가능 여부를 전달하지 않는다.

#### 공간 및 모션

- 기본 간격 단위: 4px. 주요 간격은 8/12/16/24/32px.
- 구매 성공: 코인 숫자 감소 → 상품 카드 획득 스탬프 → `바로 배치` 버튼 강조 순서, 총 500ms 안팎.
- 배치 가능 셀은 민트, 불가 셀은 피치 사선/아이콘으로 구분한다.
- 반복 부유 애니메이션은 마스코트에만 제한하고, 카드 전체가 계속 움직이지 않게 한다.

### 2.4 Tailwind 사용 여부

**결론: 이번 리디자인부터 Tailwind를 사용한다. 단, 기존 화면의 전면 마이그레이션은 하지 않는다.**

확인 결과:

- `tailwindcss@4`와 `@tailwindcss/postcss`는 설치되어 있고 PostCSS 플러그인도 설정되어 있다.
- `app/globals.css`에는 아직 Tailwind import가 없어 현재는 활성화되지 않았다.
- 기존 화면은 인라인 스타일 중심이고, 공용 색 변수와 애니메이션만 전역 CSS에 있다.

그럼에도 Tailwind를 권장하는 이유:

1. 신규 UI는 상점 카드, 인벤토리 카드, HUD, 하단 시트, 배치 상태처럼 반복 조합이 많아 인라인 객체를 계속 복제하면 상태별 스타일이 빠르게 길어진다.
2. 모바일/태블릿/데스크톱 반응형과 hover/focus/disabled 상태를 인라인 스타일보다 읽기 쉽게 관리할 수 있다.
3. 이 페이지는 비주얼을 버리고 새로 시작하는 경계이므로 도입 비용이 가장 낮다.

도입 원칙:

- 구현 승인 후 Tailwind 4의 프로젝트 내 문서를 먼저 확인하고 `globals.css` 진입점에서 활성화한다.
- 위 5색과 반경/그림자는 CSS 변수로 정의하고 Tailwind에서 재사용한다. 임의 hex 값을 JSX 곳곳에 반복하지 않는다.
- 실제 그리드 좌표, 드래그 위치, 회전값처럼 런타임 계산이 필요한 값만 `style` prop으로 둔다.
- 기존 `WorldMap`, `SoundMuseum` 등은 이번 작업에서 마이그레이션하지 않는다.

### 2.5 구현 전 확정이 필요한 제품 규칙

UI 방향과 별개로 다음 값은 실제 컴포넌트 구현 전에 결정되어야 한다.

- 도서관 평가 몇 회마다 코인을 주는지, 아이템을 주는 마일스톤은 몇 회인지
- 한 마을의 집이 `친구 초대 가능`이 되는 최소 완성 조건
- 친구 방문이 관람만 가능한지, 채팅/동시 이동/가구 상호작용까지 포함하는지
- 구매와 배치의 서버 확정 시점, 중복 클릭 및 실패 시 코인 복구 규칙
- 러그가 기존 점유 그리드와 독립 레이어인지, 가구 아래 중첩을 허용할지

이 값들은 현재 리서치 문서에서 임의로 정하지 않는다. 다음 단계에서는 우선 현재 검증 로직의 구매·보유·배치·해제를 보존하면서, 결정되지 않은 기능은 명확한 비활성/준비 중 상태로 표현하는 편이 안전하다.

## 3. 검토 체크포인트

- 상점/재화는 SumOne의 친근한 카드·마스코트 구조를 따른다.
- 방 편집은 Animal Crossing의 3/4 공간감과 예측 가능한 레이어/그리드 규칙을 따른다.
- 색은 크림·화이트·피치·민트·코코아 5색으로 제한한다.
- 기존 Nunito를 유지하고, 카드 18px/패널 24px 라운드를 기본으로 한다.
- 이번 신규 화면은 Tailwind를 사용하되 기존 화면은 건드리지 않는다.
- 이 문서 검토 전에는 컴포넌트 코드를 작성하지 않는다.
