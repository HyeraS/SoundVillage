# SoundVillage 3D art direction

이 문서는 SoundVillage 연구용 3D 게임의 시각 언어와 런타임 제작 원칙을 정의한다. 모델 납품 수치와 파일 규칙은 [`3d_asset_spec.md`](./3d_asset_spec.md)를 우선하며, 이 문서는 테마·구도·가독성·연구 조건의 일관성을 보완한다. 레퍼런스 이미지는 분위기, 색, 형태와 공간 구성의 기준일 뿐이며 특정 상용 게임의 캐릭터, 건물, 소품 또는 UI를 직접 복제하지 않는다.

## 레퍼런스 역할

| 구분 | 단일 기준 이미지 | 적용 범위 |
|---|---|---|
| B — 전체 기본 테마 | [`soundvillage-main-theme-b.png`](./art/reference/soundvillage-main-theme-b.png) | 중앙 광장, Animal, Human, Nature, Urban, Music, 플레이어 집과 집 꾸미기, 기본 Sound Museum |
| C — Unknown 전용 테마 | [`soundvillage-unknown-theme-c.png`](./art/reference/soundvillage-unknown-theme-c.png) | Unknown 마을, 미지·추론·불확실성 관련 연구 공간, 특별 전이 구역 |

레퍼런스에 없는 세부 요소는 아래 규칙과 SoundVillage 고유의 연구 목적에 맞춰 새로 설계한다. B와 C 사이에는 Sound Orb와 기본 조작 가독성만 공유하고, 테마를 구분하는 건축·발광·식생 요소는 섞지 않는다.

## B — 전체 기본 테마

### 적용 범위

- 중앙 광장
- Animal, Human, Nature, Urban, Music 마을
- 플레이어 집과 집 꾸미기
- 기본 Sound Museum

### 시각 기준

- 저장된 B 이미지를 이 범위의 단일 기준 이미지로 사용한다.
- 맑고 밝은 하늘색, 선명한 연두·초록 식생, 따뜻한 크림색 건물과 모래길을 기본 팔레트로 삼는다.
- 코랄 지붕과 청록 지붕을 주요 건물의 식별색으로 사용하고, 난간·표지판·벤치에는 따뜻한 목재를 사용한다.
- 민트와 코랄은 상호작용 요소와 친근한 동반 요소의 포인트 색으로 제한한다.
- Sound Orb는 따뜻한 황금색을 기본으로 하여 배경과 명확히 분리한다.
- 밝은 봄날 자연광을 기준으로 한다. 그림자는 부드럽지만 형태와 진행 방향을 읽을 수 있을 정도의 명암은 유지한다.
- 건물, 나무, 소품은 둥글고 친근한 저폴리 실루엣으로 제작한다. 작은 화면에서도 기능을 구분할 수 있도록 큰 형태를 먼저 읽히게 한다.
- 캐릭터 중심의 높은 3인칭 플레이 시점에서 전방 길, 상호작용 대상, 주요 출입구가 동시에 보이도록 배치한다.
- 저채도, 회색 안개, 탁한 세이지, 어두운 숲 스타일로 재해석하지 않는다. 날씨나 시간 변화가 필요하더라도 B의 밝기와 색 식별성을 훼손하지 않는다.

## C — Unknown 전용 테마

### 적용 범위

- Unknown 마을
- 미지·추론·불확실성 관련 연구 공간
- 특별 전이 구역

### 시각 기준

- 저장된 C 이미지를 이 범위의 단일 기준 이미지로 사용한다.
- 석양과 황혼을 기본 시간대로 삼고 보라, 라벤더, 청록 발광을 주요 색 언어로 사용한다.
- 천문대형 건축, 공명 파형, 반투명 구조물, 발광 식물과 결정으로 미지의 소리를 관찰하고 추론하는 공간임을 표현한다.
- 신비로운 소리 정령은 부드러운 실루엣과 제한된 발광으로 표현하며 위협적인 생물처럼 보이지 않게 한다.
- 황금색 Sound Orb의 핵심 상호작용 문법은 B와 동일하게 유지하되, 주변 발광보다 높은 형태 가독성과 일관된 피드백을 보장한다.

C의 천문대, 보라색 결정, 강한 발광 구조물은 일반 중앙 광장이나 Animal, Human, Nature, Urban, Music 마을, 플레이어 집, 기본 Sound Museum에 섞지 않는다. Unknown의 시각 요소가 연구 조건을 미리 암시하거나 정답처럼 작동하지 않도록 장식 밀도와 밝기를 통제한다.

## 공통 상호작용 문법

### Sound Orb

- annotation Sound Orb는 접근하고 소리를 들은 뒤 표현을 입력하는 연구 과제를 뜻한다.
- 기본 형태는 떠 있는 구체와 완만한 궤도 또는 파동으로 통일한다. 황금색 핵, 접근 시 외곽 강조, 상호작용 가능 상태의 명확한 HUD 문구를 함께 사용한다.
- 색만으로 상태를 구분하지 않는다. 크기 변화, 외곽선, 아이콘, 문구처럼 색각과 화면 품질에 덜 의존하는 신호를 병행한다.
- 완료 상태는 발광 감소 또는 별도 완료 표식으로 표시하되 사라진 오브젝트가 길 안내처럼 오인되지 않게 한다.

### 중앙 장식용 Orb와 annotation Orb 구분

- 중앙 장식용 Orb는 광장의 랜드마크 또는 마을 이동 허브이며 annotation 입력을 직접 열지 않는다.
- 장식용 Orb는 받침대에 고정하고 더 큰 지름, 안정된 느린 움직임, 고유 랜드마크 아이콘을 사용한다.
- annotation Orb는 플레이어 높이 주변에 떠 있고 작은 궤도, 접근 강조, `소리 듣기` 문구와 연구 진행 상태를 가진다.
- 두 종류는 이름, 접근 반경, HUD 문구, 아이콘과 상호작용 결과를 데이터와 컴포넌트 수준에서도 분리한다. 황금색을 공유하더라도 실루엣과 동작으로 즉시 구별되어야 한다.

## 캐릭터와 카메라

- 캐릭터 기준 높이는 `1.6m`, 원점은 발 중앙, 전방은 `-Z`다. 이는 `3d_asset_spec.md`의 `player` 명세를 따른다.
- 몸과 머리는 멀리서도 방향을 읽을 수 있는 단순하고 둥근 비율로 유지한다. 장식이 얼굴과 진행 방향의 실루엣을 가리지 않게 한다.
- 현재 카메라는 Perspective 고정 방향 팔로우 방식이다. 기준 FOV는 데스크톱 `38°`, 모바일 세로 `42°`, 모바일 가로 `40°`다.
- 카메라 기준 offset은 플레이어로부터 `[3.1, 5.2, 5.4]m`, look target 높이는 `0.95m`다. look-ahead는 데스크톱 `0.85m`, 모바일 세로 `0.55m`, 모바일 가로 `0.7m`다.
- 건물 입구, 나무 수관, 표지판과 장식은 이 구도에서 캐릭터와 다음 상호작용 대상을 장시간 가리지 않도록 배치한다.
- 주요 이동 경로에는 카메라와 캐릭터 사이를 완전히 막는 높은 전경 오브젝트를 두지 않는다. 불가피하면 거리 조정, 제한적 반투명 또는 배치 변경을 우선 검토한다.
- AnnotationPanel이 열린 동안 카메라와 플레이어가 멈추는 현재 동작을 시각 효과나 환경 애니메이션이 방해하지 않아야 한다.

## 모델 제작 및 GLB 교체

- 좌표계는 Y-up이며 `1 unit = 1m`다. 캐릭터와 방향성 소품의 전방은 Blender `-Z`로 통일한다.
- 캐릭터 원점은 발 중앙, 건물과 사물 원점은 바닥면 중앙, Sound Orb 원점은 구체 중심에 둔다.
- 내보내기 전에 회전과 크기를 적용하고 런타임 scale `(1, 1, 1)`을 목표로 한다.
- 모델별 정확한 크기, 파일명, 애니메이션 이름, collider와 텍스처 제한은 `3d_asset_spec.md`의 표를 따른다.
- placeholder와 GLB는 동일한 asset key, 원점, 전방, 기준 크기와 기능적 실루엣을 공유해야 한다. 교체 시 월드 배치나 연구 데이터 ID를 바꾸지 않는다.
- 시각적 미세 조정은 `assetManifest.mjs`의 `scale`, `rotation`, `positionOffset`으로 수행할 수 있지만 collider도 함께 검증한다.
- 충돌체는 render mesh와 분리한다. 단순 원형 또는 AABB를 우선하고, 장식 메시의 세부 굴곡을 충돌체로 복제하지 않는다.
- Blender 원본, 고해상도 텍스처와 베이크 중간 산출물은 웹 런타임 GLB와 분리하여 Git LFS 또는 제작 스토리지에 보관한다.

## 성능과 접근성

- 저사양 노트북과 모바일에서 안정적인 상호작용을 우선한다. 목표는 일반 모바일에서 안정적인 `30fps` 이상, 지원 가능한 데스크톱에서 `60fps`에 근접하는 것이다.
- 일반 소품 텍스처는 `512px` 이하, 캐릭터와 주요 건물은 `1024px` 이하를 기본으로 하고 atlas와 재질 공유를 우선한다.
- 나무, 꽃, 울타리, 결정처럼 같은 geometry와 material이 반복되는 오브젝트는 배치 데이터와 `InstancedMesh`를 우선 사용한다.
- 재질 수와 draw call을 제한한다. 모바일에서 보이지 않는 작은 장식은 거리 또는 화면 크기에 따라 생략할 수 있다.
- 투명 재질은 겹침 순서 문제와 overdraw를 고려해 C의 핵심 구조물에만 제한적으로 사용한다. 실시간 굴절, 다중 패스 블룸, 넓은 화면 후처리와 고비용 파티클은 기본 경로에 넣지 않는다.
- `prefers-reduced-motion`에서는 Orb 부유, 파형, 정령과 식생 흔들림의 진폭과 속도를 줄이거나 정지한다. 상호작용 가능 여부는 정지 상태에서도 형태와 문구로 읽혀야 한다.
- 모바일 HUD와 D-pad가 캐릭터, 출입구, annotation Orb를 가리지 않도록 safe area와 현재 반응형 look-ahead를 함께 검증한다.

## 연구 조건 관리

- 테마는 공간 정체성을 제공하지만 소리의 정답, 범주 또는 기대 표현을 암시해서는 안 된다.
- 연구 조건별로 이동 거리, 오브젝트 크기, 접근 반경, 광원 대비, 가림 정도와 장식 밀도를 가능한 한 동일하게 유지한다.
- 특정 조건만 더 밝거나 더 큰 annotation Orb를 사용하지 않는다. C의 발광 배경에서도 annotation Orb의 가독성은 유지하되 상호작용 난이도는 B와 동등하게 맞춘다.
- UI 문구, 아이콘, 캐릭터 반응과 완료 피드백은 테마에 관계없이 같은 의미와 순서로 제공한다.
- 아트 변경 전후에는 데스크톱과 모바일에서 발견 시간, 오입력 가능성, 가림과 멀미 요인을 확인한다. 연구 결과에 영향을 줄 수 있는 시각 변경은 변경 기록에 남긴다.

## 검수 체크리스트

- 적용 영역이 B 또는 C 중 하나로 명확히 분류됐는가?
- B 영역에 저채도 회색 안개나 C 전용 천문대·결정·강한 발광 구조물이 섞이지 않았는가?
- 모델의 크기, 원점, Y-up과 `-Z` 전방이 자산 명세와 일치하는가?
- placeholder를 GLB로 바꿔도 배치, collider, 상호작용 ID와 연구 데이터 계약이 유지되는가?
- 현재 높은 3인칭 카메라에서 캐릭터와 목적지가 장시간 가려지지 않는가?
- 중앙 장식용 Orb와 annotation Orb가 실루엣, 동작, HUD와 결과로 구별되는가?
- 모바일에서 프레임 안정성과 HUD/D-pad 가독성을 유지하는가?
- reduced-motion에서도 모든 상태와 상호작용을 이해할 수 있는가?
- 특정 상용 게임의 캐릭터, 건물, 소품 또는 UI를 직접 복제하지 않았는가?
- 테마 차이가 연구 조건의 난이도나 의미 단서 차이로 이어지지 않는가?
