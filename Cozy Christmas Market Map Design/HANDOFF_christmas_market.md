# 사람 마을(Human) — 크리스마스 마켓 리스킨 인수인계

- 디자인 원본: `크리스마스 마켓 마을.dc.html` (좌표·레이아웃 상수 전부 로직 클래스 안에 있음)
- 에셋: `assets/winter_global.png`(winter full, 576×512) / `assets/global.png`(타일셋 4224×1712) / `assets/global2.png`(겨울 타일셋 2368×1136)
- 대상 브랜치: `asset-swap` — `components/ZoneMap.js`의 Human 존 렌더링만 교체. `spawnSoundItems`·블록/그룹 필터·Supabase 관련 코드는 **한 줄도 건드리지 않는다.**

## 0. Claude Code에 시키는 순서

이 파일과 `크리스마스 마켓 마을.dc.html`, `assets/` 3장을 저장소에 넣고 아래 순서로 요청하면 된다. 단계마다 스크린샷으로 확인받고 다음으로 넘어가는 방식이 안전하다.

1. **에셋 복사·등록** — `public/assets/winter/`에 3장을 복사하고, 4장의 좌표표를 `components/AssetRegistry.js`에 `WINTER_MARKET` / `WINTER_TILES`로 등록. `ASSET_READY` 폴백 패턴 유지.
2. **지형** — `buildHumanZone()` 신설. 2장의 `ground(tx,ty)` 규칙과 3장의 타일 매핑을 그대로 옮긴다. 16px 셀 단위로 그리므로 32px 게임 타일 하나에 4장이 들어간다.
3. **오브젝트·충돌** — 5장의 배치표를 `NATURE_HOUSES`와 같은 형태의 상수로 만들고, footprint만큼 `solid` 마킹. 아이스링크는 테두리만 충돌(6장).
4. **소리 아이템 연결** — 7장. 디자인 파일의 `SOUND_SPOTS`는 버리고 기존 `spawnSoundItems` 결과를 쓰되, "길·마당 위 스폰 제외" 체크만 새 지형 함수로 갈아끼운다.
5. **캐릭터** — 8장. `WORLD_CHARACTER`(8프레임 걷기)로 교체.
6. **검증** — `RESEARCHER` ID로 잠금 우회 후 headless 스크린샷, 콘솔 에러 0건, 아이템 스폰·진행바·집계가 기존과 동일하게 동작하는지 확인.

## 1. 그리드
`TILE=32`, `MAP_W=48`, `MAP_H=36` (Nature 존과 동일). 광장 중심 `CX=24, CY=18`.
화면은 전체 맵이 아니라 플레이어 추적 뷰포트(700×450 월드픽셀 = 약 22×14타일)를 1.6배로 확대. WorldMap의 카메라 로직과 같은 방식.

## 2. 지형 규칙 `ground(tx,ty)` → 0 눈밭 / 1 눈길 / 2 광장 보도블록 / 3 흙길
중심에서의 거리 `d = hypot(tx+0.5-24, ty+0.5-18)`:

| 조건 | 결과 |
|---|---|
| `d < 6.2` | 2 광장 |
| `d < 7.6` | 0 (광장과 도로를 나누는 눈 띠) |
| `d < 9.8` | 3 광장 둘레 흙길 |
| `|tx-24| ≤ 2 && ty ≥ 18` | 3 남쪽 메인 프롬나드 |
| `|tx-24| ≤ 1.5 && ty < 18` | 1 북쪽 눈길 |
| `|ty-17.5| ≤ 1.5` | 1 동서 눈길 |
| `BRANCH` 사각형 안 | 1 지선 눈길 |
| 그 외 | 0 눈밭 |

```js
const BRANCH = [ // [x0,x1,y0,y1]
  [5,17,12,13], [8,9,13,17],    // 북서 정원·진저브레드
  [33,44,12,13], [33,34,13,17], // 북동 아이스링크 앞
  [11,12,22,30], [36,37,22,30]  // 남서·남동 숲 산책로
];
```

**동선 위계가 이 맵의 핵심이다.** 사람이 몰리는 메인 프롬나드와 광장 둘레만 흙이 드러난 흙길이고, 지선은 다져진 눈길, 나머지는 눈밭이다. 폭도 프롬나드 5타일 > 눈길 3타일로 다르다. 이 위계를 유지하지 않으면 다시 "공원"처럼 보인다.

9-slice 규칙(광장·눈 더미 공통):
```js
col = same(left) ? (same(right) ? 1 : 2) : 0;
row = same(up)   ? (same(down)  ? 1 : 2) : 0;
src = [gx + col*16, gy + row*16];
```
흙길이 흙길 아닌 셀과 닿는 변에는 2~5px 흰 띠를 덧그려 길가에 쌓인 눈을 표현한다(눈↔흙 전이 타일이 팩에 없기 때문).

## 5. 오브젝트 배치
`[키, 타일X, 타일Y, footprintW, footprintH, 스케일]` — 스프라이트는 footprint의 **가로 중앙·아래쪽 정렬**로 그린다(`x = (tx+fw/2)*32 - w/2`, `y = (ty+fh)*32 - h`). 정렬 기준이 아래쪽이라 지붕이 위로 넘치는 건 정상이고, 넘치는 부분은 충돌하지 않는다.

- 상점 스케일 **2.25**, 스캐터 나무 **2**, 중앙 마켓 트리 **1.5**(가장 높아야 하는 랜드마크), 가로등·소품 1.2~1.5.
- 스톨 열: 왼쪽 `x=17`, 오른쪽 `x=27~28`, 행 `y=26`과 `y=31` — 프롬나드(x22~26)를 마주 본다.
- 광장 북쪽: `stall_menu(16,7)`, `shop_candy(28,7)` — 뜨거운 음료·과자 코너.
- 남쪽 게이트: 캔디케인 `(21,33)`, `(27,33)` 스케일 3, 울타리는 x21~27만 열어둔다.
- 정렬 원칙: **게이트에서 중앙 트리까지 시선이 막히지 않아야 한다.** 프롬나드 중앙(x23~25)에는 충돌 오브젝트를 두지 않는다.

전체 목록은 디자인 파일의 `PLACED` 배열을 그대로 복사하면 된다.

## 6. 충돌
`solid: Uint8Array(48*36)`. 오브젝트 footprint + 맵 테두리 1타일(남쪽 게이트 제외).
아이스링크만 예외:
```js
const RINK = { tx:34, ty:5, w:10, h:6, scale:2, gate:[38,39] };
// 테두리 한 줄만 solid, 아래쪽 gate 구간은 열어둔다 → 안에서 스케이트 가능
```
링크 스프라이트는 **바닥 레이어**(지형 위, 오브젝트 아래)에 그린다. 링크 영역 ±1타일은 나무 스캐터에서 제외.

플레이어 판정은 발 밑 사각형 4점(`px±7`, `py-3 / py+7`)을 축별로 따로 검사 — 벽을 스치며 걷는 느낌이 나고 모서리에 끼지 않는다.

## 7. 소리 아이템
- 디자인 파일에는 `SOUND_SPOTS` 14곳이 하드코딩돼 있지만 **실제 게임에서는 쓰지 않는다.** 기존 `spawnSoundItems`의 그룹/블록 필터 결과를 그대로 쓰고, 스폰 후보에서 `ground!==0 || solid` 인 타일과 링크 내부만 제외한다.
- 근접 판정 34px → 프롬프트 → Space/Enter로 전사 패널. 잠금(구름) 연출은 사용자 결정으로 제거, 전체 오픈.
- 아이콘은 스프라이트가 아니라 캔버스로 그린 픽셀 버블(광원 + 음표). 근접하면 색이 따뜻하게 바뀐다 — 이 피드백은 유지할 것.

## 8. 캐릭터
현재는 `npc1`(`307,289,11,15`)을 2.4배로 그리고 걷는 동안 1px 바운스 + 좌우 반전만 한다.
`Character v.2` 팩을 넣으면 `WORLD_CHARACTER`(32×32, 8프레임, FR 100ms, 몸/옷/머리 3레이어)로 교체. 그리기 지점 한 곳만 바꾸면 나머지는 그대로 동작한다.

## 9. 렌더 레이어 순서
1. 지형 16px 타일 → 2. 흙길 눈 띠 → 3. 아이스링크 → 4. `sort`(=발 위치 y) 오름차순으로 오브젝트·NPC·소리 아이템·플레이어 → 5. 시간대 틴트 + 가로등/트리 광원(`lighter` 합성) → 6. 눈 파티클.

깊이 정렬은 전부 "발이 닿는 y좌표" 하나로 통일한다. 오브젝트마다 다른 기준을 쓰면 큰 스톨 뒤로 플레이어가 사라지는 버그가 난다.
