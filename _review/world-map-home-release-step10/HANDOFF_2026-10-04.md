# SoundVillage World Home Release 인수인계

작성 기준일: 2026-10-04 (Asia/Seoul)

이 문서는 새 Codex 채팅에서 SoundVillage World Map Home native object release 작업을 안전하게 이어가기 위한 현재 기준이다. 구현과 World 검증은 사실상 완료됐으며, 남은 일은 Git에서 의도적으로 제외된 Character V2 원본 에셋을 격리 snapshot에 읽기 전용 입력으로 공급해 마지막 회귀를 재검증한 뒤 기존 staged 45개만 커밋하는 것이다.

## 현재 결론

상태는 **PARTIAL**이다. 제품 코드나 World Home 후보의 결함 때문에 중단된 것이 아니다.

- World Home release 후보 45개는 정확히 stage되어 있다.
- 승인된 World 핵심 해시 8개는 모두 일치한다.
- World, 브라우저, Economy, 보안, ESLint, production build 검증은 통과했다.
- 커밋, push, PR, deploy는 하지 않았다.
- 유일한 blocker는 exact snapshot에 `.gitignore` 대상인 `assets/Character v.2/`가 없어 Character Stage 3 회귀 2건이 실패한 것이다.
- 테스트나 baseline은 약화하지 않았다.

이 blocker는 **격리 검증 환경의 외부 입력 누락**으로 처리해야 한다. 테스트를 skip하거나 원본 에셋을 Git에 추가하면 안 된다.

## 완료된 제품 계약

### Authority

- `data/world-map-v4/worldObjects.mjs`가 visual layer, depth, ground contact, collision, interaction, navigation, minimap의 authored authority다.
- `data/world-map-v4/sourceAssets.mjs`가 승인된 source 경로, 크기, SHA-256의 authority다.
- production consumer는 generated literal projection만 사용한다.
- Home과 Library만 native다.
- 나머지 16개 object는 legacy 상태다.
- legacy Home 데이터는 rollback compilation을 위해 build-only로 보존된다.

### Home 좌표

- visualBox: `(1472,1395)–(1824,1696)`, 352×301
- collider: `(1520,1472)–(1776,1696)`, half-open
- groundContact와 sortY: `(1648,1696)` / `1696`
- door, approach, minimap point: `(1648,1760)`
- roadConnectionPoint: `(1824,1760)`
- siteBounds: `(1440,1344)–(1856,1824)`
- 남측 통과로: `(1344,1728)–(1856,1792)`
- 동측 보호 도로: `(1824,1440)–(1952,1888)`

### 렌더 순서

`terrain → environment → object ground → depth-sorted world/characters → object foreground → global foreground → overlay → interaction/debug UI`

Home은 ground와 building 두 레이어이며 object union 기준으로 atomic culling한다. Home 전용 foreground는 없고 legacy Home 중복 렌더는 0개다.

### Collision

- logical object의 rect/polygon shape가 authority다.
- half-open 좌표를 사용한다.
- 29×17 clearance를 한 번 적용한 뒤 4px max-pool한다.
- collision reason과 packed mask가 일치해야 한다.
- 모든 walkable cell은 하나의 connected component여야 한다.
- 목적지 8곳에 실제 도달할 수 있어야 한다.
- site-ground는 collider를 만들지 않는다.

## 마지막 blocker의 원인

실패한 검증은 `scripts/character-v2-assets.test.mjs`의 다음 두 계약이다.

1. `scripts/validate-character-v2-runtime-assets.py`가 runtime 결과를 원본 master의 RGBA 픽셀과 비교한다.
2. asset builder 결정성 테스트가 source master의 작업 전후 hash를 비교하고 builder를 재실행한다.

필요한 원본은 다음 경로에 있다.

`/Users/hyera/Documents/SoundVillage-house-decor-2d/assets/Character v.2`

이 경로는 `.gitignore`의 `/assets/` 규칙에 의해 Git에서 제외된다. 현재 약 1,041개 파일, 18MB이며 원본 checkout에서는 Character 테스트가 통과한다.

따라서 `git archive`나 HEAD+staged 파일만 복원한 snapshot에는 이 입력이 존재하지 않는다. Character Stage 3 구현 당시 exact snapshot에서는 이 ignored 원본 master를 읽기 전용 검증 입력으로 연결해 전체 검증했다.

## blocker 해결 방법

1. 현재 HEAD+staged 45개만 포함하는 새 격리 snapshot을 만든다.
2. 원본 checkout의 `assets/Character v.2/` 전체 파일에 대해 정렬된 상대 경로와 SHA-256 manifest를 `/private/tmp`에 만든다.
3. 해당 폴더를 snapshot의 동일 상대 경로로 복사한다.
4. 복사본 manifest가 원본과 일치하는지 확인한다.
5. snapshot의 복사본을 read-only로 만든다.
6. Character asset/Stage 3 테스트를 skip 없이 실행한다.
7. 실행 후 원본 checkout과 snapshot 복사본의 manifest가 모두 작업 전과 같은지 확인한다.
8. staged tree와 45개 allowlist가 전후 동일한지 확인한다.
9. 전체 exact snapshot gate를 한 번 최종 실행한다.
10. 모두 통과하면 기존 staged 45개만 커밋한다.

정확한 검증 환경 표현은 다음과 같다.

> HEAD + staged 45개 제품 트리 + Git에서 의도적으로 제외된 해시 검증·읽기 전용 Character V2 source master 입력

“HEAD+staged만으로 원본 source까지 재현된다”고 표현하면 안 된다.
