# SoundVillage 월드맵 `우리 집` 비주얼 통합 — Step 0 설계·측정 명세

작성일: 2026-09-26 (Asia/Seoul)  
좌표계: 월드 좌상단 원점, 월드 픽셀, 1타일 = 32px, 전체 3840×2880px

## 결론

**352×301px 권장안이 적절하다.** 현재 의미 있는 가시 높이 301px을 유지하면서 `alpha > 8` 원본 비율 959:820을 사실상 그대로 복원한다. 종횡비 오차는 -0.0066%로 승인 기준 1%보다 충분히 작다. 현재 323×301은 원본보다 8.25% 좁고, 448×383은 352×301보다 가로·세로가 약 27% 커서 개인 주택이 게스트하우스급 존재감으로 커지고 동측 주도로와 부지 장식을 과도하게 점유한다.

다만 **352×301은 크기·좌표 기준의 승인안이지, 기존 그림을 그대로 축소해서 최종 사용하자는 뜻은 아니다.** 기존 그림을 `alpha > 8`로 크롭해 352×301로만 축소하면 평균 경계 강도 21.455/255, 강한 에지 비율 9.6505%로 여전히 승인 기준을 넘는다. 새 아트 또는 재작업 아트는 같은 352×301 가시 envelope 안에서 도서관·게스트하우스 수준으로 에지와 세부 밀도를 낮춰야 한다.

## 목표

- 우리 집의 실제 표시 크기, 부지, 앵커, 현관·접근점, 시각 footprint, 충돌 기준, `sortY`를 하나의 월드 좌표계로 확정한다.
- 집 본체와 월드 부지 장식의 책임을 분리한다.
- 현재 배경에서 제거·유지·이동할 요소와 2타일 폭 접근로를 확정한다.
- 다음 아트/구현 단계가 수치로 승인될 수 있도록 비교 대상과 합격 기준을 고정한다.

## 비목표

- 프로덕션 코드, 매니페스트, 빌드 파이프라인을 수정하지 않는다.
- 런타임 WebP/PNG, 원본 집 이미지, 충돌 마스크를 교체하거나 수정하지 않는다.
- 새 집 이미지를 생성하지 않는다.
- 집 위치, 카메라 FOV, 상호작용점 또는 충돌을 실제 런타임에 적용하지 않는다.
- `image-rendering: pixelated`, 정수 배율 고정, 카메라 확대를 해결책으로 사용하지 않는다.

## 확인한 현재 상태

### 알파 경계

| 기준 | 원본 bbox | 크기 |
|---|---:|---:|
| `alpha > 0` | `(0,41)–(1331,1086)` | 1331×1045 |
| `alpha > 8` | `(246,111)–(1205,931)` | 959×820 |
| `alpha > 16` | `(246,112)–(1205,931)` | 959×819 |

`alpha > 8`과 `alpha > 16`은 위쪽 한 행만 다르므로 `alpha > 8`을 의미 있는 크롭 기준으로 채택한다. 무임계 `getbbox()`는 좌측 캔버스 끝과 하단까지 퍼진 저알파 노이즈를 포함하므로 사용하면 안 된다.

### 현재 런타임 배치

- 선언 월드 박스: `(1440,1368)–(1888,1752)`, 448×384
- 런타임 에셋: 448×384 WebP, SVG `preserveAspectRatio="none"`
- 의미 있는 가시 bbox (`alpha > 8`): `(1523,1394)–(1846,1695)`, **323×301**
- 가시 bbox bottom-center: 약 `(1684.5,1695)`
- 현재 `sortY`: 1752
- 현재 접근점: `(1664,1792)`
- 현재 충돌: `(1536,1472)–(1792,1752)`

의미 있는 원본 비율은 1.169512, 현재 가시 비율은 1.073090이다. 현재 집은 원본 대비 가로 비율이 8.25% 눌려 있다. 또한 실제 그림 하단 1695와 선언 `sortY` 1752 사이에는 57px 차이가 있어 시각 접지점과 정렬 기준이 분리돼 있다.

### 접근로

접근로는 다음 세 직사각형의 합집합을 기본 마스크로 한다. 실제 아트에서는 모서리를 부드럽게 굽힐 수 있지만, 어느 단면에서도 64px(2타일)보다 좁아지면 안 된다.

1. 현관 apron: `(1632,1696)–(1696,1792)`
2. 동쪽 connector: `(1632,1728)–(1792,1792)`
3. 기존 도로 seam: `(1792,1696)–(1856,1792)`

중심선은 `groundContact (1664,1696) → door/approach (1664,1760) → road connection (1824,1760)`이다. 이로써 현관에서 기존 남북 보행로까지 끊김 없는 2타일 폭 경로가 생긴다.

## 책임 분리와 레이어 구조

### `home-site-ground`

- 핵심 부지의 잔디·흙·낮은 경계 재구성
- 최소 64px 접근로와 기존 도로 seam
- 낮은 울타리, 화단, 관목
- 월드 조명 방향·색온도와 맞춘 접지 그림자
- 플레이어를 가리지 않는 낮은 장식

### `home-building`

- 집 본체, 지붕, 벽, 창, 문
- 현관과 최소한의 계단
- 자체 지면 패치, 긴 돌길, 울타리, 화단, 관목, 독립 조명, 별도 접지 그림자는 포함하지 않음
- `visualBox` 352×301, `groundContact` `(1664,1696)`, `sortY=1696`

### `home-foreground` — 필요한 경우만

- 플레이어를 실제로 덮어야 하는 전면 울타리 상단, 높은 가로등 상단, 관목 끝만 포함
- `home-building`에 합치지 않고 별도 `sortY` 또는 부분 마스크를 사용
- 필요하지 않으면 만들지 않음

### `home-site metadata`

한 데이터 원천에 `siteBounds`, `visualBox`, `groundContact`, `footprint`, `collision`, `doorPoint`, `approachPoint`, `roadConnectionPoint`, `sortY`를 함께 둔다. 개념 관계는 다음과 같다.

- `visualBox`: 렌더·컬링용 가시 영역
- `groundContact`: 아트의 bottom-center 배치 기준
- `footprint`: 지면에 투영된 점유 영역
- `collision`: footprint를 따르며 최대 차이 16px(0.5타일)
- `doorPoint`: 월드에서 보이는 현관의 지면점
- `approachPoint`: 플레이어 발 중심 상호작용점; `doorPoint`와 최대 8px
- `sortY`: 건물과 캐릭터 깊이 정렬선; `groundContact.y`

## 비교 대상과 측정 기준

### 비교 대상

- **게스트하우스:** 소형 건물의 실루엣·벽면 디테일 주기·낮은 대비 기준
- **도서관:** 지붕/파사드 에지 무게, 계단과 광장 접속, 접지 그림자 기준
- **중앙 정원 서측 샘플** `(1280,1536)–(1792,2048)`: 잔디·관목·화단 밀도와 그림자 팔레트 기준
- **중앙 광장 샘플** `(1792,1408)–(2112,1792)`: 접근로 재료·줄눈·seam 기준

### 재현 가능한 에지 측정

- RGB를 Rec.709 휘도로 변환한다.
- x/y 중앙 차분의 유클리드 gradient magnitude를 사용한다.
- 투명 에셋은 `alpha > 16` 픽셀만 집계한다.
- 평균 경계 강도는 0–255 범위의 gradient 평균이다.
- 강한 에지는 magnitude ≥48로 정의한다.

| 대상 | 평균 경계 강도 | 강한 에지 비율 | 세부 에지 비율(≥32) |
|---|---:|---:|---:|
| 현재 집 런타임 | 21.4389 | 9.1938% | 22.1092% |
| 기존 그림 352×301 후보 | 21.4551 | 9.6505% | 22.4673% |
| 기존 그림 448×383 후보 | 19.8732 | 8.3593% | 19.8049% |
| 게스트하우스 | 9.7338 | 0.8471% | 4.3848% |
| 도서관 | 8.0010 | 0.8541% | 3.1227% |
| 중앙 정원 서측 샘플 | 7.4775 | 0.3963% | 2.4132% |

집의 현재 평균 경계 강도는 게스트하우스/도서관 중앙값 8.8674보다 약 142% 높다. 따라서 크기 교정과 화풍 교정은 별도 승인 항목이어야 한다.

런타임 투명판의 `alpha > 16` 월드 가시 범위는 집 323×301, 게스트하우스 784×552, 도서관 1539×698이다. 게스트하우스와 도서관 투명판에는 건물뿐 아니라 정원·광장까지 구워져 있으므로 이 전체 수치를 순수 건물 크기로 해석하면 안 된다. 다만 같은 월드 스케일에서 448×383 집은 개인 주택과 게스트하우스의 건축 위계를 불필요하게 좁히고, 352×301은 현재 높이를 유지하면서 명확히 작은 주택으로 남는다.

카메라별 352×301의 예상 화면 크기는 1280×720에서 약 332×284px, 1440×900에서 약 422×361px, 390×844에서 약 214×183px, 844×390에서 약 204×175px이다. 따라서 1px 월드 선은 모바일에서 1px보다 작게 축소된다. 중요한 윤곽의 최소 시각 주기를 월드 기준 4px로 정하고, 작은 꽃·기와·창살을 1–2px 고주파 패턴으로 반복하지 않는 이유다.

## 승인 기준

다음 항목을 모두 통과해야 다음 구현을 완료로 본다.

- 집 가시 크기: 352×301px 기준, 제작 공차 가로·세로 각각 ±4px
- 원본/런타임 종횡비 변형: 절대값 1% 이하
- 평균 경계 강도: 7.10–10.64/255(게스트하우스·도서관 중앙값 ±20%)
- 강한 에지 비율: 8% 이하, 권장 목표 5% 이하
- 중요한 지붕선·문틀·계단 모서리의 시각 주기: 월드 표시 기준 최소 4px
- `doorPoint`와 실제 상호작용점 차이: 8px 이하
- `visualFootprint`와 충돌 경계 차이: 축별 16px(0.5타일) 이하
- `sortY = groundContact.y`
- 핵심 부지 내부 이중 울타리·이중 화단·이중 관목: 0개
- 현관에서 기존 보행로까지 연속된 64px 이상 접근로 존재
- 접근로와 기존 도로 seam에서 줄눈 단절, 색온도 급변, 별도 떠 있는 그림자 없음
- 1280×720, 1440×900, 390×844, 844×390에서 가는 윤곽이 깜빡이거나 1px 선으로 붕괴하지 않음
- `image-rendering: pixelated` 또는 정수 배율 강제 없이 통과

## 다음 구현 단계

사용자 승인 후에만 다음 순서로 진행한다.

1. 352×301 `home-building` 아트 사양을 확정하고 비교 건물 기준으로 새 아트/재작업을 수행한다.
2. `home-site-ground`에서 핵심 부지 장식을 제거·재배치하고 64px 접근로와 접지 그림자를 작성한다.
3. 필요한 전면 가림 픽셀만 `home-foreground`로 분리한다.
4. `home-site metadata`를 한 데이터 원천으로 구현한다.
5. 그 다음에만 빌드 파이프라인, 매니페스트, 좌표, 충돌을 변경한다.
6. 데스크톱·모바일 실렌더 캡처와 에지/종횡비/접근성 검사를 다시 실행한다.
