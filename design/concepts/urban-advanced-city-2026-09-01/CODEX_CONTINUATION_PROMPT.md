## 가장 중요한 남은 작업 1 — 시각 품질을 확정 시안 수준으로 끌어올리기

현재 리뷰 스크린샷은 기능적 화이트박스에 가깝고 아직 확정 디자인의 완성도에 도달하지 못했습니다. 다음 문제를 명시적으로 개선하세요.

- 건물들이 큰 단색 직사각형과 단순 창문 격자로 보여 고층 유리 건축의 입체감·재질·층별 리듬이 부족함
- 미디어광장, 유리 푸드코트, 현대 극장, 전기버스 베이가 서로 다른 장소로 충분히 식별되지 않음
- 고가 메트로와 전동차는 존재하지만 플랫폼 캐노피·지지 구조·계단·도시 배경과의 깊이감이 약함
- 확정 시안의 쿨 화이트·시안 발광, 바이올렛 미디어 패널, 창문 조명, 젖은 도로 반사와 야간 분위기가 부족함
- 실제 아이템 15개가 인접 타일과 선형 슬롯에 몰려 소리 마커가 건축과 길보다 더 강하게 보임
- 전체 해금 상태에서는 83개 마커가 도시 아트를 거의 덮으므로 크기·간격·상태별 가시성 위계가 필요함

확정 시안과 현재 스크린샷을 나란히 비교하면서 한 번의 수정으로 끝내지 말고 시각적으로 반복 검수하세요. 단, 탑다운 2D 시점, 기존 픽셀 굵기, 캐릭터 크기와 48×36 타일 구조는 유지합니다.

현재 코드 기반 드로잉만으로 시안 충실도를 내기 어렵다면 `imagegen` 스킬을 사용해 현대식 고층 건물, 고가 메트로, 유리 푸드코트, 현대 극장, 전기버스 같은 **개별 투명 배경 픽셀 스프라이트**를 생성·검수해도 됩니다. 이 경우:

- 확정 시안 전체를 평면 배경으로 사용하지 말고 독립된 지면·건물·소품·전경 레이어를 유지하세요.
- 최종 에셋을 `public/assets/urban-city-v2/`에 저장하고 manifest/source 메모를 남기세요.
- 16px 또는 32px 네이티브 그리드와 정수배 확대를 유지하세요.
- 외부의 라이선스 불명확한 에셋은 다운로드하지 마세요.

## 남은 작업 2 — 실제 사운드 수를 유지하면서 마커 밀도 개선

Urban A/B 각각의 실제 83개 사운드와 6블록 값은 절대 줄이거나 합치지 마세요. 디자인 이미지의 6개 오브는 대표 표식일 뿐입니다.

대신 다음을 만족하도록 안전 슬롯과 마커 렌더를 개선하세요.

- 블록별 15/15/15/15/15/8개가 모두 고유 좌표에 배치됨
- 인접 마커가 시각적으로 겹치지 않도록 실제 렌더 반경을 고려한 최소 간격 적용
- 특정 세로줄·가로줄·한 지점에 마커가 몰리지 않고 구역 내 보행 공간에 균형 있게 분산됨
- 마커는 건물·나무·가로등·차량·철도·도로 차선·출입구·병목과 겹치지 않음
- 남쪽 스폰에서 해당 블록 해금 시점에 모두 접근 가능함
- block 1에서는 15개만 읽기 좋게 보이고 잠긴 블록은 기존 잠금 안개와 상태 규칙을 유지함
- 전체 해금 상태에서도 도시 아트가 주인공으로 남도록 마커 지름·글로우·완료 상태 불투명도를 조정함
- 수집 가능 범위는 마커를 작게 만들더라도 플레이 감각이 나빠지지 않게 유지함

마커를 단순히 숨겨 테스트를 통과시키지 말고 실제 모든 사운드가 수집 가능한 상태를 유지하세요.

## 남은 작업 3 — 코드·회귀 감사

다음을 특별히 확인하고 필요한 경우 Urban 범위 안에서 수정하세요.

- `components/GameEngine.js`에서 전역 `SPEED`가 3.9에서 5.85로 바뀐 diff가 보입니다. 이 변경의 출처를 확인하세요. Urban 작업이 만든 변경이라면 다른 모든 존의 속도를 바꾸지 말고 기존 전역 값을 복원한 뒤 Urban 전용 속도가 필요할 경우 로컬 상수로 분리하세요. 다른 병렬 작업의 변경이면 임의로 되돌리지 말고 보고만 하세요.
- `UrbanZoneMap.js`의 모바일 HUD 보정이 `div:first-of-type`와 `nth-of-type`에 의존합니다. DOM 순서 변화에 깨지지 않는지 확인하고, 가능하면 명시적 class/data hook 또는 좁게 범위가 지정된 안전한 구조로 바꾸세요. 다른 존의 공용 HUD 외형은 바꾸지 않습니다.
- `app/page.js`에는 Nature QA, Animal/Lab 분기 등 다른 작업의 변경도 섞여 있습니다. Urban import·분기에 필요한 최소 변경만 유지하고 다른 변경에는 손대지 마세요.
- `package.json`의 Nature/Music/Lab 관련 스크립트와 다른 파일 변경을 보존하세요.
- `debugStart`와 QA 컨트롤은 `/urban-test`에만 영향을 주고 제품 경로에는 노출되지 않아야 합니다.
- annotation 중 이동·Enter·ESC 입력이 올바르게 잠기고, 패널을 닫은 뒤 같은 아이템이 즉시 중복 실행되지 않는지 확인하세요.
- 출구 트리거가 입장 직후 발동하지 않고 ESC/남쪽 출구/완료 모달 흐름이 다른 존과 일관적인지 확인하세요.
- Canvas DPR, 비정수 화면 크기, 카메라 clamp에서 픽셀이 흐려지거나 한쪽으로 치우치지 않는지 확인하세요.
- 콘솔 error, warning, hydration 오류, ResizeObserver 오류, 애니메이션 루프 누수를 확인하세요.

## 남은 작업 4 — 실제 루트 앱 전체 흐름 검증

브라우저 검증 지침을 읽고 in-app browser를 사용하세요. 먼저 `/urban-test`에서 회귀를 확인한 후 반드시 루트 앱에서 실제 흐름을 검증합니다.

### `/urban-test`

- Group A와 B
- block 1과 block 6
- entrance와 metro QA 시작 위치
- 1440×844, 1920×1080, 390×844
- 이동, 충돌, 카메라 clamp, D-pad, Enter 수집, 완료 상태

### 실제 `/` 제품 흐름

각각 `ALLAUDIO_A`, `ALLAUDIO_B`로 다음을 확인하세요.

1. 로그인
2. WorldMap 진입
3. Urban 포털까지 이동하고 실제 UrbanZoneMap 진입
4. 키보드 이동과 최소 3종 이상의 충돌 확인: 건물, 차량/시설, 메트로 또는 가로등
5. 활성 소리 아이템 접근 및 Enter 수집
6. AnnotationPanel 열림
7. 제출하지 않고 닫았을 때 Urban으로 정상 복귀하고 아이템 상태가 잘못 완료되지 않음
8. 가능한 경우 실제 제출 흐름까지 확인하되 테스트 데이터가 외부 DB를 오염시키지 않도록 기존 연구용 검증 관례를 따름
9. 잠긴 블록 진입 차단
10. ESC 또는 남쪽 입구를 통한 정상 퇴장과 WorldMap 복귀

외부 DB 쓰기가 안전하지 않거나 연결 상태 때문에 제출 검증이 불가능하면 무리하게 우회하지 말고, 패널 열기·취소까지 검증한 뒤 정확한 제한을 보고하세요.

## 자동 검증과 빌드

최종 수정 후 다음을 다시 실행하세요.

- `npm run test:urban-production`
- Urban 관련 파일 targeted ESLint
- `npm run build`
- 필요하면 전체 `npm run lint`도 실행하되, 기존 무관 오류를 고치지 말고 Urban 변경으로 생긴 오류와 분리해 보고

Urban production test에는 최소한 다음이 포함되어야 합니다.

- A/B 각 83개와 블록별 15/15/15/15/15/8 보존
- 입력 순서와 무관한 결정론적 배치
- 좌표 중복 없음
- 렌더 크기를 고려한 마커 최소 간격
- 맵 경계·solid·road lane·rail·병목·출입구 회피
- 각 해금 단계에서 모든 보행 타일과 아이템의 BFS 접근 가능성
- 남쪽 spawn이 exit trigger와 겹치지 않음
- 잠긴 블록은 이동 불가, 해금 후 이동 가능

## 완료 조건

다음이 모두 충족되어야 완료입니다.

- 기능만 작동하는 수준이 아니라 확정 2안의 건축·교통·야간 조명과 장소 정체성이 명확함
- 기존 마을과 픽셀 굵기·탑다운 시점·캐릭터 비율은 어울리지만 Urban은 분명한 현대 대도시로 구별됨
- 실제 83개 아이템과 6블록 로직이 누락 없이 유지되고 화면 밀도가 관리됨
- 실제 루트 앱의 A/B Urban 진입, 수집 패널, 취소 복귀, 잠금, 퇴장 흐름을 검증함
- 자동 테스트, targeted lint와 build가 통과함
- 다른 존과 병렬 WIP를 훼손하지 않음
- 최종 리뷰 스크린샷과 구현 핸드오프 문서로 결과를 증명함

완료 시 `design/concepts/urban-advanced-city-2026-09-01/IMPLEMENTATION_HANDOFF.md`를 작성해 구조, 변경 파일, 에셋 출처, 충돌·스폰 규칙, 테스트 결과, 브라우저 검증 결과, 알려진 제한을 기록하세요.

안전한 로컬 수정과 비파괴 검증은 중간 승인을 기다리지 말고 끝까지 진행하세요. 외부 다운로드, 파괴적 명령, 라이선스가 불명확한 에셋 사용, Urban 범위를 넘는 대규모 리팩터가 필요할 때만 질문하세요.
