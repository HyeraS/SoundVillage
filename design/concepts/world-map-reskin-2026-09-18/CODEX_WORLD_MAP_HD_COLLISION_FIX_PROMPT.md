# SoundVillage 월드맵 고해상도·보이지 않는 충돌 수정용 Codex 프롬프트

아래 지시를 현재 SoundVillage 저장소에서 끝까지 수행하라. 분석이나 제안만 남기지 말고 실제 코드·에셋·검증 자료까지 완성한다.

---

당신은 시니어 2D 게임 맵 아티스트이자 게임플레이/충돌 시스템 엔지니어다. 현재 SoundVillage 월드맵의 디자인과 연결 기능은 유지하되, 아래 두 사용자 체감 결함을 실제 실행 환경에서 해결하라.

1. 월드맵 배경이 확대되어 흐리고 저해상도로 보인다.
2. 화면에는 분명 걸을 수 있는 길로 보이는데 이동 중 캐릭터가 보이지 않는 벽에 걸려 더 진행하지 못하는 구간이 여러 곳 있다.

## 현재 구현에서 이미 확인된 문제

- 배경 원본은 `2896×2172`인데 게임 월드는 `120×90` 타일, 타일당 32px이므로 `3840×2880`이다. 즉 원본을 월드 좌표에서 약 1.326배 확대하고 있으며, 넓은 화면에서는 `30×22` 타일 카메라가 다시 확대된다.
- 현재 SVG의 `feConvolveMatrix` 샤픈 필터와 `imageRendering: 'crisp-edges'`는 실제 디테일을 복원하지 못한다. 테두리 번짐이나 계단 현상을 더 만들 수 있으므로 이것을 해상도 해결책으로 간주하지 않는다.
- 현재 충돌은 실제 배경의 길 픽셀을 기준으로 하지 않고 `WORLD_ROUTE_SEGMENTS`, 타원형 순환로, 사각형 부지 등 수학 도형으로 근사한다.
- `isWorldPlayerWalkable`은 발 영역 전체가 아니라 좌우 두 점만 검사한다. 반면 실제 길은 불규칙한 곡선과 폭을 가지므로 시각 경계와 판정 경계가 어긋난다.
- 기존 검증은 목적지마다 통과 가능한 경로 하나가 존재하는지는 확인하지만, 플레이어가 선택할 수 있는 모든 눈에 보이는 길이 끊김 없이 통과 가능한지는 증명하지 못한다. 따라서 기존 테스트가 PASS여도 사용자는 다른 길에서 막힐 수 있다.

## 절대 보존할 것

- 현재 월드맵의 구도, 색감, 랜드마크 위치, 길의 형태, 건물과 자연물 배치, 120×90 월드 크기, 30×22 기본 카메라 체감.
- 여섯 마을, 도서관, 집의 위치와 기존 포털/진입 콜백 및 화면 전환.
- Music-first 잠금 및 해제 규칙, 진행률, HUD, Enter/Space/모바일 확인, 키보드·터치 이동, duo 좌표 동기화, 분석 이벤트, Supabase 흐름.
- 실제 장애물인 건물, 물, 절벽·돌, 울타리, 빽빽한 숲은 통과할 수 없어야 한다.
- 개발용 QA 파라미터는 production에서 무시되는 기존 보안 경계를 유지한다.

## 1단계: 실제 실행 상태 재현과 진단

1. `http://localhost:3101/?natureQa=1`을 브라우저에서 직접 열고 데스크톱 화면에서 현재 흐림을 캡처한다. 서버가 다른 포트에서 실행 중이면 기존 프로세스를 함부로 종료하지 말고 사용 중인 포트를 확인한다.
2. 이동 중 막히는 위치를 최소 5곳 이상 찾아 월드 좌표와 스크린샷을 남긴다. 중앙 광장과 순환로 사이의 곡선, 각 마을로 갈라지는 분기, 다리·게이트, 벤치와 화단 옆 좁은 길을 반드시 포함한다.
3. 개발 모드 전용으로 다음을 한눈에 볼 수 있는 충돌 디버그 모드를 추가한다.
   - 쿼리: `worldCollisionDebug=1`
   - 실제 이동 가능 영역 반투명 초록색
   - 실제 차단 영역 반투명 빨간색
   - 플레이어 발 충돌 박스 또는 발 중심점
   - 플레이어 월드 좌표
   - 직전 입력 방향과 어느 축이 왜 차단되었는지
   - production에서는 완전히 비활성화
4. 디버그 오버레이를 실제 배경 위에 겹친 전체 맵 이미지를 만들어, 시각적인 길과 충돌이 어긋난 곳을 먼저 목록화한다.

## 2단계: 진짜 고해상도 배경으로 교체

단순 리사이즈, `image-rendering` 변경, CSS/SVG 샤픈 필터만으로 완료 처리하지 않는다.

1. 현재 v2 배경을 구도 고정 기준 이미지로 사용해 고해상도 마스터를 제작한다. 최소 목표는 `5792×4344`이며, 성능과 타일링이 허용하면 `7680×5760`을 사용한다. 원본과 정확히 같은 4:3 비율을 유지한다.
2. 확대 과정은 경로·랜드마크·건물 외곽·물가·울타리 위치를 이동시키지 않는 정밀 업스케일/복원이어야 한다. 새로운 건물이나 길을 임의로 생성하거나 기존 요소를 삭제하지 않는다.
3. 생성형 보정이 필요하다면 전체 맵을 한 번에 재생성하지 말고, 충분한 오버랩을 둔 타일 단위 정밀 편집/업스케일 후 다시 결합한다. 이음새, 반복 무늬, 형태 변형을 전수 확인한다.
4. 고해상도 마스터를 기존 이미지 크기로 축소한 비교본, 50% 오버레이, 차이 히트맵을 만든다. 길 중심선과 랜드마크 실루엣의 위치 오차는 기존 v2 기준 2px 이내여야 한다.
5. 런타임에서는 확대 보간이 최소화되도록 사용한다. 큰 단일 이미지가 메모리나 첫 로딩에 문제를 만들면 고해상도 마스터를 일정한 격자의 타일 이미지로 나누고, 카메라 주변 타일만 렌더한다. 타일 경계에는 겹침 또는 정확한 클리핑을 사용해 1px 이음새도 보이지 않게 한다.
6. 로딩 중 저해상도 이미지가 순간적으로 크게 확대되어 보이지 않게 프리로드/대체 표시를 처리한다.
7. 최종 렌더에서 샤픈 필터에 의존하지 않는다. 고해상도 원본을 쓸 때는 자연스러운 축소 보간을 사용하고, `crisp-edges` 때문에 회화풍 에셋이 거칠어지지 않는지 비교한다.
8. 1280×720, 1440×900, 1920×1080, DPR 1과 DPR 2에서 건물 문, 벤치, 가로등, 꽃, 길 경계가 선명한지 실제 캡처로 검수한다.

## 3단계: 보이는 길과 1:1로 맞는 충돌 시스템

현재의 타원·선분·사각형 근사식을 조금씩 덧대는 방식으로 끝내지 않는다. 배경과 좌표가 정확히 등록된 단일 충돌 원본을 만든다.

1. `world-walkable-mask` 또는 동등한 명시적 내비게이션 마스크를 만든다.
   - 기준 좌표는 `3840×2880` 월드와 정확히 1:1로 정렬한다.
   - 포장도로, 흙길, 광장, 다리, 게이트 내부, 각 진입 마당을 모두 포함한다.
   - 건물 본체, 물, 울타리, 절벽·큰 바위, 통과 불가능한 숲은 제외한다.
   - 자동 색상 추출 결과를 그대로 신뢰하지 말고, 배경 위 오버레이를 보며 사람이 길 경계를 보정한다.
2. 플레이어 스프라이트 전체가 아니라 발 영역을 기준으로 하되, 좌우 두 점 샘플 방식은 폐기한다. 다음 중 더 안정적인 구조를 선택한다.
   - 발 중심이 이동할 수 있는 영역을 플레이어 발 반경만큼 미리 침식한 clearance mask
   - 또는 발 사각형이 덮는 마스크 셀 전체를 검사하는 방식
3. 권장 방식은 clearance mask다. 길 가장자리와 곡선에서 걸리는 느낌을 줄이기 위해 실제 보행로 안쪽에 6~10 world-px 정도의 허용 여유를 주되, 그 여유가 울타리·물·건물 내부까지 열지 않게 한다.
4. 마스크 해상도는 이동 속도보다 충분히 촘촘해야 한다. 런타임/빌드 결과에서 1셀은 최대 4 world-px로 하고, 필요하면 이동을 sub-step으로 나눠 얇은 차단 영역을 건너뛰지 않게 한다.
5. X/Y 축 분리 이동과 벽 미끄러짐은 유지하되, 곡선 길에서 한 축이 차단된 뒤 양쪽 축 모두 멈추는 코너 걸림이 생기지 않게 실제 프레임 단위로 검증한다.
6. 배경과 충돌은 서로 다른 하드코딩 좌표를 갖지 않게 한다. 런타임과 검증 스크립트가 동일한 마스크/생성 결과/이동 함수를 import하도록 리팩터링한다.
7. 더 이상 쓰지 않는 `WORLD_ROUTE_SEGMENTS`, 임시 예외 선분, 중복 `PATH_TILES` 충돌 정의는 안전하게 제거하거나 렌더 전용임을 명확히 분리한다. 새 마스크와 이전 근사식이 동시에 판정을 내려 서로 충돌하게 두지 않는다.
8. 눈에 보이는 모든 길 영역은 하나의 연결된 보행 네트워크여야 한다. 의도적으로 막힌 장식 길이 있다면 시각적으로도 울타리·수풀·문 등 명확한 막힘을 표현하고 QA 보고서에 이유를 기록한다. 보이지 않는 벽은 허용하지 않는다.

## 4단계: 테스트를 사용자 체감 기준으로 강화

기존 PASS 결과만 다시 출력하지 말고 아래 테스트를 추가한다.

1. 정적 정합성 검사
   - 배경과 내비게이션 마스크의 크기·비율·원점 일치
   - 모든 포털/도서관/집 진입 영역 연결
   - 모든 시각적 길 중심선이 clearance mask 안에 포함
   - 보행 네트워크에 의도치 않은 작은 고립 영역이나 1~2셀 병목이 없음
2. 실제 이동 함수 검사
   - production과 동일한 `SPEED`, delta time, 발 크기, X/Y 분리 이동을 사용
   - 60fps뿐 아니라 끊김을 가정한 큰 delta time에서도 sub-step 검증
   - 상하좌우와 대각선 입력 모두 검사
   - 직선, 곡선, 교차로, 다리, 게이트, 포털 앞에서 500ms 이상 의도치 않게 위치가 멈추지 않음
3. 전체 길 커버리지 검사
   - 목적지당 경로 하나만 찾지 말고 모든 보행 가능 영역을 샘플링한다.
   - 길 중심선과 좌우 가장자리에서 일정 간격으로 실제 캐릭터 발 크기를 적용한다.
   - 각 순환 방향과 모든 분기를 양방향으로 주행한다.
4. 브라우저 E2E
   - 기본 스폰에서 텔레포트 없이 실제 이동 입력으로 여섯 마을, 도서관, 집까지 각각 도달
   - 진입 키를 눌러 올바른 실제 마을 컴포넌트로 전환
   - 다시 월드맵으로 복귀
   - `worldStart`는 문제 위치 재현과 캡처에는 사용할 수 있지만, 전체 경로 성공 증명에는 사용하지 않는다.
5. 회귀 검사
   - 잠긴 마을은 여전히 진입 불가
   - Music-first 해제 후 여섯 마을 진입 가능
   - 모바일 버튼과 키보드 Enter/Space가 동일한 진입 함수를 사용
   - 실제 장애물은 통과 불가
   - duo/분석/Supabase 계약 유지

## 5단계: 시각 및 성능 합격 기준

- 데스크톱 실제 화면에서 기존 캡처보다 명확히 선명해야 하며, 확대된 저해상도 픽셀·뭉개진 문양·샤픈 halo가 없어야 한다.
- 고해상도 교체 후에도 기준 맵의 길, 랜드마크, 건물 배치는 바뀌지 않아야 한다.
- 보이는 보행로에서 사용자가 방향키를 계속 누를 때 이유 없이 멈추는 구간이 0곳이어야 한다.
- 충돌 오버레이에서 길 안쪽에 빨간 띠나 끊긴 조각이 없어야 한다.
- 물·건물·울타리 등 실제 장애물 침범도 0건이어야 한다.
- 이미지 타일링을 도입했다면 카메라 이동 중 흰 틈, 타일 경계, 늦게 뜨는 조각이 없어야 한다.
- 장시간 이동 중 콘솔 오류가 없어야 하고, 프레임이 눈에 띄게 끊기거나 메모리가 계속 증가하지 않아야 한다.

## 완료 보고 형식

완료 시 다음만 명확히 보고한다.

1. 저해상도의 실제 원인과 적용한 해결 방식
2. 보이지 않는 충돌의 실제 원인과 교체한 판정 구조
3. 새 에셋 및 변경 파일 경로
4. 실제로 재현해 없앤 막힘 위치 목록
5. 여섯 마을·도서관·집의 실제 이동/진입/복귀 결과
6. 데스크톱·모바일·DPR별 해상도 검수 결과
7. 실행한 테스트와 PASS/FAIL
8. 남은 제한 또는 외부 서비스 때문에 검증하지 못한 항목
9. 대표 전/후 이미지와 충돌 오버레이의 절대 경로

`기존 테스트가 통과했다`, `경로가 하나 존재한다`, `이미지를 더 크게 저장했다`, `샤픈 필터를 넣었다`만으로 완료 처리하지 않는다. 실제 화면의 선명도와 사용자가 선택할 수 있는 모든 보행로의 연속 이동을 브라우저에서 확인한 뒤에만 완료라고 보고한다.
