## 2. 확정된 디자인

핵심은 **‘2안의 S자 개울·두 다리·농장 구조 + 3안에서 가져온 밝은 색감과 풍부한 꽃’**이다.

유지할 특징:

- 화면 위쪽 중앙에서 시작해 가운데를 지나 남동쪽으로 흐르는 맑은 청록색 S자 개울.
- 개울의 위쪽과 아래쪽에 놓인 정확히 두 개의 넓은 목교.
- 두 다리와 양쪽 흙길이 이어져 다시 돌아올 수 있는 순환 동선.
- 북서쪽의 물레방앗간과 작은 물받이.
- 서쪽의 황금빛 밀밭, 채소밭, 남서쪽의 작은 집.
- 북동쪽의 크림색 집과 유리 온실.
- 동쪽의 사과 과수원, 벤치와 열린 풀밭.
- 밝은 연두색 잔디, 따뜻한 버터·살구빛 모래길, 맑고 생기 있는 낮의 분위기.
- 크림색 회벽, 꿀빛 목재, 적갈색 또는 청회색 지붕.
- 흰 데이지, 복숭아색·분홍색 꽃, 노란 들꽃과 소량의 보라색 꽃이 작은 군락으로 섞인 식생.
- 집 앞, 온실 주변, 물가 굽이, 과수원 가장자리, 숲 가장자리에 집중된 꽃 군락.
- 꽃과 장식 사이에 남아 있는 넓은 이동 여백과 명확한 길.

밝고 생기 있어야 하지만 잔디 전체를 형광색으로 만들거나 화면에 흰색 블룸을 덮지 마라. 그림자와 지붕의 어두운 면은 형태를 읽을 정도로 유지하고, 회색·갈색 필터로 다시 칙칙해지지 않게 해줘. 청록색은 주로 물과 일부 자연 강조색에 사용하고, 건물·흙길·목재까지 같은 청록색으로 덮지 마라.

꽃은 풍부하게 보이되 길, 다리, 건물 문 앞, 울타리 출입구, 소리 아이템 주변을 막는 카펫처럼 깔지 마라. 농장 경작지와 야생화 군락의 형태가 구분되어야 한다.

3안의 풍차, 별도 큰 연못, 중앙 우물 광장을 가져오지 마라. 세 번째 다리, 가축 우리, 새 농사 시스템, 상점 시스템, 새로운 NPC도 추가하지 마라. 이 디자인은 Farm 분위기의 Nature 마을이며 Animal 마을을 복제하는 것이 아니다.

실내 방, 폐쇄된 정원, 거대한 한 채의 농가가 아니라 여러 작은 생활 공간과 농장이 개울을 사이에 두고 연결된 야외 마을이어야 한다. 3D나 등각 투영으로 바꾸지 말고, 기존 게임과 같은 탑다운 3/4의 2D 픽셀 표현을 사용해줘.

작은 배치 조정은 실제 캐릭터 크기, 충돌, 카메라, 소리 배치 용량을 확보할 때만 허용한다. S자 개울, 두 다리, 물레방앗간, 서쪽 농장, 동쪽 과수원과 온실이라는 중요한 공간 관계는 유지하고, 조정 이유를 기록해줘.

## 3. 이미지가 아니라 게임 맵으로 제작

최종 PNG는 1448×1086 크기의 전체 조감 목업이다. 이 이미지를 게임 좌표계로 그대로 사용하거나, 이미지 속 캐릭터·HUD·D-pad·소리 구슬까지 통째로 배경에 넣는 방식을 사용하지 마라.

다음 요소를 분리해서 제작해줘:

- 지면: 밝은 잔디, 모래길, 밭 흙, 개울 수면, 물가.
- 통행 지형: 열린 잔디, 주 길, 보조 길, 두 다리의 바닥.
- 장애물: 건물 몸체, 나무줄기, 바위, 울타리, 작물 영역, 다리 난간, 수면.
- 앞뒤 가림: 지붕, 나무 수관, 처마, 키 큰 갈대.
- 생활 소품: 벤치, 표지판, 물통, 수레와 낮은 농장 장식.
- 비충돌 장식: 꽃, 작은 풀, 수면 반짝임과 낮은 지면 무늬.
- 게임 요소: 기존 캐릭터, 실제 소리 아이템, 상호작용 안내.
- 화면 UI: 기존 ZoneHUD, DPad, 완료·퇴장 모달.
- 논리 데이터: 통행 가능 영역, 충돌 영역, 스폰·출구, 구역 경계, 소리 배치 후보.

기존 에셋을 먼저 조사하고, 시안의 형태·색상·픽셀 굵기에 적합한 것은 재사용해줘. 재사용하기 편하다는 이유로 최종 시안과 다른 건물이나 칙칙한 팔레트를 그대로 쓰지 마라. 부족한 물레방앗간·온실·식생·농장 소품은 사용할 수 있는 이미지 제작 도구와 해당 스킬로 제작·편집하고, 실제 게임 규격에 맞춰 정리해줘.

기존 공용 에셋을 직접 덮어쓰지 말고 Nature 전용 파일이나 명확히 분리된 새 버전으로 저장해줘. 생성·편집한 원본과 프롬프트를 프로젝트 안에 남기고, 실제 사용하는 런타임 에셋과 구분해줘. 출처가 불분명한 외부 이미지나 승인되지 않은 유료 에셋을 가져오지 마라.

단순 도형, 이모지, CSS 그라디언트만으로 만든 임시 건물과 나무를 완성 아트로 남기지 마라. 시안의 물레방앗간·온실·나무·작물·목교가 픽셀아트 오브젝트로 읽혀야 한다. 에셋이나 도구가 부족해 시각적 목표를 달성하지 못하면 그 부분을 숨기지 말고 구체적으로 알려줘.

픽셀 기준:

- 현재 코드의 32px 논리 타일을 기준으로 한다.
- 기존 Nature와 다른 마을의 48×36타일, 1536×1152 world px 규격을 우선 유지한다.
- 현재 Nature 원본 지형 에셋은 16px 타일을 32 world px로 표시한다. 기존 렌더링 방식을 확인하고 픽셀 굵기를 맞춘다.
- 조감 이미지의 1448×1086 크기를 런타임 월드 크기나 타일 좌표로 그대로 사용하지 않는다.
- 기존 PixelChar의 표시 크기와 발 접점을 기준으로 문·집·나무·다리·울타리 크기를 맞춘다.
- 기본 플레이 카메라 24×18타일과 플레이어 추적 방식을 유지한다.
- 픽셀 보간에 의한 흐림, 비정수 확대, 서로 다른 픽셀 굵기, 타일 이음새와 얇은 반픽셀 선을 방지한다.
- `imageSmoothingEnabled=false`와 `image-rendering: pixelated`에 맞게 제작한다.
- 전체 맵을 한 화면에 억지로 축소해서 캐릭터나 소리 구슬이 기존 마을보다 작아지게 하지 않는다.
- 좌상단 광원, 간결한 접촉 그림자와 3–5단계 재료 명암을 사용하고, 소리 아이템보다 환경 발광이 강해지지 않게 한다.

## 5. 실제 이동과 충돌

캐릭터는 건물·나무·바위·울타리·작물·다리 난간·물을 뚫지 못하고 돌아가야 한다. 열린 잔디, 모래길과 다리 바닥은 걸을 수 있어야 한다.

- 충돌은 캐릭터의 발 기준으로 계산한다.
- 현재 Nature의 `PLAYER_BOX`는 18×10px이며 `canStand`는 발 주변을 검사한다. 최신 코드를 확인하고 시각 스프라이트 전체를 충돌 크기로 오인하지 마라.
- 나무 수관이나 지붕 전체를 큰 사각 충돌 영역으로 쓰지 말고 나무 몸통, 건물 바닥과 분리한다.
- 큰 오브젝트는 캐릭터 발의 y 위치에 맞춰 앞뒤 가림이 자연스럽게 보이게 한다.
- 수관·지붕·갈대 뒤에서 캐릭터나 소리 아이템이 완전히 사라지지 않게 배치하거나 가림 처리를 한다.
- x축과 y축 이동을 분리해 장애물에 닿았을 때 막힌 축만 제한하고 자연스럽게 옆으로 미끄러질 수 있게 한다.
- 모서리, 대각선 이동, 낮은 프레임과 큰 dt 상황에서도 수면·벽·난간을 뚫지 않아야 한다.
- 주 동선은 유효 폭 3타일 이상, 보조 동선은 최소 2타일을 목표로 한다. 시각적 길 폭이 아니라 실제 발 충돌 박스로 통과 가능한 폭을 확인한다.
- 두 목교는 바닥만 통행 가능하고 난간과 기둥은 충돌해야 한다.
- 다리의 양 끝이 마른 통행 지면과 연결되고, 물가 돌·갈대·꽃 때문에 입구가 좁아지지 않게 한다.
- 밭과 과수원의 울타리에는 의도한 출입구가 있어야 하고, 울타리나 작물 내부로 잘못 들어갈 수 없어야 한다.
- 건물 문 앞에는 최소 3×3타일의 시야·접근 영역을 둔다. 이번 범위에서 새 실내 진입 기능을 만들 필요는 없다.
- 꽃, 낮은 풀, 작은 지면 무늬는 비충돌 장식으로 취급하고 이동을 방해하지 않게 한다.
- 남쪽 스폰 지점과 나가기 감지 영역을 충분히 분리해 입장하자마자 퇴장 안내가 뜨지 않게 한다.
- 새 배치에 맞춰 스폰, 출구, 상호작용과 충돌 좌표를 함께 갱신한다. 캐릭터가 물·나무·건물에 끼인 채 시작하지 않아야 한다.
- 전사 패널, 수집 확인 또는 퇴장 확인이 열렸을 때 배경 이동과 중복 입력이 기존과 같이 차단되어야 한다.

통행 판정은 명시적인 맵 데이터나 오브젝트 footprint로 관리하고 배경 이미지의 색상을 읽어 추정하지 마라. 보이는 경계와 실제 충돌 경계의 차이는 가능한 0.5타일 이내로 맞춰줘.

## 6. 소리 아이템과 구역 진행

최종 이미지 속 소리 구슬과 “구역 6/6” 표시는 전체 조감용 예시다. 실제 소리 수나 블록 수를 이미지에 맞춰 하드코딩하지 마라.

- 전달받은 실제 `sounds` 목록을 기준으로 모든 대상 소리를 누락·중복 없이 배치한다.
- sound_id, group, block 값과 블록 순서를 유지한다.
- 동일 그룹·동일 소리 목록으로 재입장했을 때 위치가 안정적으로 재현되도록 시드 기반 결정을 유지한다.
- 물, 건물, 작물, 울타리, 다리 난간, 닫힌 고립 영역이나 수관·지붕에 완전히 가려지는 위치에는 생성하지 않는다.
- 각 아이템 중심 주변 최소 1타일, 주 접근 방향 2타일의 실제 상호작용 여백을 목표로 한다.
- 시안의 꽃과 장식보다 소리 구슬이 높은 국소 대비를 갖도록 한다. 환경 꽃의 노란 중심이나 창문빛이 소리 구슬과 같은 크기·링·발광을 반복하지 않게 한다.
- 소리 구슬은 기존 Nature의 중립적인 금빛 부유 형태, 링 파동과 분리된 발밑 그림자를 유지하거나 그보다 명확하게 다듬는다.
- 특정 소리의 종류나 정답을 암시하는 동물, 날씨, 악기 아이콘을 구슬 옆에 배치하지 않는다.
- 수집한 아이템, 활성 아이템, 잠긴 아이템과 잠금 안개의 기존 의미를 유지한다.
- 아이템 배치와 잠금 안개가 동일한 블록 공간 정의를 사용하도록 한다.
- 후보 공간이 부족하면 꽃과 장식 밀도 또는 통행 지형을 조정한다. 동일 좌표 중복, 소리 누락, 장애물 위 배치, 임의 좌표 fallback으로 조용히 넘어가지 마라.

전체 개방 상태에서만 동선을 확인하지 마라. 블록 1부터 최종 블록까지 각 진행 단계에서 현재 수집해야 할 모든 아이템에 실제로 도달할 수 있어야 한다. 입구에서 가까운 구역부터 진행된다는 기존 감각을 유지하고, 잠금 안개나 지형 때문에 다음 진행이 막히지 않아야 한다.

소리 구슬이 물레방앗간, 개울, 작물 옆에 보이더라도 실제 소리와 환경 오브젝트의 의미를 일대일로 연결하지 마라. 이 맵의 장식은 분위기이며 전사 답변의 정답 힌트가 아니다. 새로운 환경음이나 농장 소리를 임의로 추가하지 마라.

## 7. 검증과 완료 조건

구현 전 현재 Nature의 기준 화면, git 상태와 관련 파일의 기존 변경을 기록하고, 구현 뒤 아래 항목을 실제로 확인해줘.

기능 검증:

- 메인 앱의 정상 경로로 WorldMap에서 Nature에 들어갔을 때 새 맵이 나온다.
- `/nature-test`에서도 실제 Nature 소리로 새 맵이 렌더링된다.
- 키보드 방향키/WASD와 모바일 D-pad로 이동·방향 전환·나가기가 작동한다.
- 물, 건물, 나무줄기, 바위, 울타리, 작물, 다리 난간과 모서리의 충돌이 정확하다.
- 두 다리의 바닥을 양방향으로 통과하고 양쪽 강변 순환 동선을 완주할 수 있다.
- 열린 잔디와 의도한 울타리 출입구가 실제로 통행 가능하다.
- 실제 그룹 A/B 각각에 대해 전체 아이템 수, 고유 ID, 블록, 배치와 접근 가능성이 맞다.
- 각 블록 단계, 일부 수집 상태와 재입장 상태에서도 진행이 막히지 않는다.
- 아이템 접근, 선택, 전사 취소·완료, 중복 선택 방지와 진행도 반영이 기존 흐름과 호환된다.
- 퇴장 확인과 WorldMap 복귀가 정상이고 입장 직후 퇴장 팝업이 뜨지 않는다.
- 다른 마을과 공통 UI에 회귀 문제가 없다.

이동·스폰 검증은 육안에만 의존하지 말고 캐릭터 발 충돌 크기를 반영한 도달성 검사를 추가해줘. BFS 또는 동등한 탐색으로 다음을 검사하고 실제 조작 테스트를 함께 수행해줘:

- 스폰 → 위쪽 다리 양쪽 접근점.
- 스폰 → 아래쪽 다리 양쪽 접근점.
- 스폰 → 출구.
- 스폰 → 각 블록 단계의 모든 활성 소리 후보.
- 통행 영역의 고립된 walkable 섬.
- 충돌 지형 내부에 생성된 아이템.
- 동일 목록 재입장 시 아이템 위치 재현.
- 아이템 누락, 중복 ID와 중복 좌표.

시각 검증:

- 최종 시안과 구현의 전체 조감 화면을 나란히 비교한다.
- 실제 플레이 카메라에서 물레방앗간, 위쪽 다리, 아래쪽 다리, 서쪽 밭, 동쪽 과수원, 북동쪽 온실과 남쪽 입구를 각각 캡처한다.
- S자 청록 개울, 정확히 두 다리, 양안 순환 길과 주요 건물의 상대 관계가 유지되는지 확인한다.
- 잔디가 최종 시안처럼 밝고 생기 있는지, 흙길이 따뜻한지, 수면이 맑은 청록인지 비교한다.
- 흰색·분홍·노랑·보라 꽃의 밀도와 군락이 시안과 비슷하면서 이동 경계를 가리지 않는지 확인한다.
- 기존 동물·음악 마을과 동일한 플레이 줌에서 픽셀 굵기, 나무·집·문·캐릭터 비례를 비교한다.
- 캐릭터와 소리 구슬이 수관, 지붕, HUD와 D-pad에 가려지지 않는지 확인한다.
- 데스크톱 1440×900, 모바일 세로 390×844, 가능한 모바일 가로 화면에서 카메라 끝, 왜곡, HUD 잘림과 조작 버튼 겹침을 확인한다.
- 브라우저 콘솔 오류, 에셋 로딩 실패, 타일 이음새, 흐림, 이동 중 떨림과 카메라 좌표 어긋남을 확인한다.

가능한 관련 테스트, lint와 production build를 실행해줘. 실행할 테스트가 부족하면 Nature 전용 충돌·블록·아이템 배치 회귀 테스트를 추가하되, 구현 코드를 그대로 복제하는 무의미한 테스트는 만들지 마라. 기존 실패와 이번 변경으로 생긴 실패를 구분해줘.

정적 지면과 오브젝트를 매 프레임 다시 생성하지 마라. 물결이나 식생 움직임을 추가한다면 화면당 효과 수와 비용을 제한하고, 소리 구슬의 움직임·시인성과 경쟁하지 않게 한다.

외부 저장 검증은 로컬 mock이나 격리된 테스트 환경을 우선 사용하고 실제 연구 참가자 데이터에 테스트 제출을 하지 마라. 백엔드 검증 권한이나 안전한 테스트 환경이 없다면 해당 부분을 미검증으로 명시해줘.

`/nature-test`의 전체 개방 상태와 빈 종료 콜백만 확인하고 실제 제품 연동 전체를 검증했다고 판단하지 마라. 메인 앱의 WorldMap → Nature → 소리 선택 → 기존 전사 패널 → 취소 또는 안전한 테스트 완료 흐름까지 확인해야 한다.

## 8. 작업 범위와 최종 보고

현재 작업 폴더에는 다른 작업의 미커밋 변경과 미추적 파일이 있을 수 있다. 시작 시 `git status`와 관련 diff를 확인하고 기존 수정·미추적 파일을 보존해줘. 관련 없는 정리, 파일 삭제, 공용 코드 전면 리팩터링, reset이나 checkout으로 사용자 작업을 되돌리는 행동은 하지 마라.

로컬 구현과 비파괴 검증은 진행하되, 배포, push, 운영 DB 변경, 데이터 삭제, 유료 에셋 구매와 외부 서비스 쓰기는 별도 승인 없이 하지 마라.

분석이나 계획만 제시하고 끝내지 말고, 이 범위의 구현과 검증을 끝까지 진행해줘. 일상적인 구현 선택은 최신 코드와 검증 결과를 바탕으로 스스로 판단해도 된다. 필요한 도구나 에셋이 없거나 요구사항 사이에 해결할 수 없는 충돌이 있다면 안전하게 진행 가능한 작업을 먼저 완료하고 남은 차이와 필요한 결정을 구체적으로 보고해줘.

완료 조건을 충족하지 못한 부분은 “완벽하게 적용했다”고 표현하지 마라. 시안에 비해 부족한 에셋, 시각적 차이, 미검증 장치와 실제 위험을 명확히 남겨줘.

최종 보고에는 다음을 포함해줘:

1. 실제 연결된 Nature 화면과 로컬 확인 방법.
2. 최종 플레이 화면, 전체 조감과 모바일 스크린샷.
3. 최종 시안과 구현 화면의 비교 및 남은 차이.
4. 변경 파일, 새 에셋과 생성 원본·프롬프트 목록.
5. 충돌, 두 다리 순환, 스폰·출구, 아이템·블록 진행과 반응형 테스트 결과.
6. 실행한 lint·build·자동 검사 명령과 결과.
7. 원본 시안에서 조정한 부분과 그 이유.
8. 미검증 항목, 알려진 제한과 배포 전 확인할 사항.

목표는 색만 밝힌 기존 Nature 맵이 아니라, 확정된 ‘꽃피는 개울 농장’의 공간과 분위기를 유지하면서 기존 SoundVillage의 소리 탐험·전사 게임이 정상 작동하는 완성도 높은 2D 자연 마을이다.
