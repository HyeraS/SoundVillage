## 4. ImageGen으로 새로 제작할 전체 에셋 세트

사용 가능한 imagegen 스킬과 내장 이미지 생성·편집 도구를 사용해줘. 최종 시안 이미지를 **모든 생성 호출의 주 시각 참조**로 전달하고, 텍스트 설명만으로 비슷한 일반 농장 에셋을 만들지 마라.

서로 성격이 다른 에셋은 한 장의 거대한 콜라주로 한 번에 생성하지 말고, 건물별·지형 패밀리별·소품 패밀리별로 별도 생성 또는 편집 호출을 사용해줘. 첫 결과가 시안과 다르면 그대로 채택하지 말고 한 번에 하나의 차이를 수정해 반복해줘.

새로 제작해야 하는 최소 에셋:

### 건물

1. 북서쪽 물레방앗간
   - 따뜻한 크림 회벽, 꿀빛 목재 골조, 적갈색 기와 지붕.
   - 왼쪽의 큰 물레, 짧은 청록색 물받이, 문 옆 꽃과 통.
   - 최종 시안과 같은 낮고 넓은 실루엣.

2. 북동쪽 주택
   - 크림색 벽, 청회색 박공지붕, 따뜻한 갈색 문.
   - 입구 화분과 작은 꽃장식.
   - 기존 `house_cream.png`과 다른 최종 시안 전용 디자인.

3. 북동쪽 온실
   - 밝은 민트 회색 프레임, 투명한 청록 유리, 내부의 노랑·초록 식물.
   - 기존 온실 에셋을 확대·색칠한 결과가 아니라 시안과 같은 낮고 넓은 형태.

4. 남서쪽 오두막
   - 작은 크림 벽체, 청회색 지붕, 따뜻한 목재 문과 입구 꽃.
   - 캐릭터 대비 크기와 지붕 높이가 최종 시안과 일치.

### 지형과 경계

5. 밝은 연두색 잔디 타일 패밀리
   - 조용한 기본 타일과 밝음·중간·약간 어두운 변주.
   - 드문 작은 풀잎·점무늬 변형.
   - 반복 이음새가 보이지 않는 연결 가능한 에셋.

6. 따뜻한 모래색 길 오토타일 패밀리
   - 중앙, 직선, 모서리, 안쪽·바깥쪽 곡선, 끝, 교차부.
   - 잔디가 조금 스며든 유기적인 경계.
   - 큰 직사각형 도장을 반복한 형태가 아니라 최종 시안처럼 부드러운 루프를 구성할 수 있어야 한다.

7. 개울과 강가 오토타일 패밀리
   - 맑은 청록 수면의 기본·잔잔한 반짝임 변주.
   - 직선 둔치, 안쪽·바깥쪽 굽이, 좁아짐·넓어짐, 발원부와 하류 연결.
   - 회갈색 돌, 밝은 잔디 프린지, 얕은 물 띠.
   - 갈대와 물가 풀이 지형과 자연스럽게 결합하되 충돌 영역을 속이지 않아야 한다.

8. 목교 패밀리
   - 최종 시안과 같은 밝은 꿀빛 판자, 어두운 접촉 그림자, 짧은 기둥과 양쪽 난간.
   - 위쪽·아래쪽 다리가 같은 재료 패밀리이되 반복이 기계적으로 보이지 않게 최소 변주 제공.
   - 다리 바닥과 난간을 충돌·전경 처리를 위해 분리할 수 있게 제작.

9. 밭 흙과 두둑 패밀리
   - 밝고 따뜻한 갈색 흙, 어두운 가장자리, 정돈된 이랑.
   - 밀·채소·옥수수 밭의 형태를 구별할 수 있는 변형.

### 식생과 농장 오브젝트

10. 일반 활엽수 패밀리
    - 최종 시안처럼 둥글고 풍성한 밝은 연두 수관.
    - 4–6개의 실루엣·명암 변주.
    - 나무 몸통과 수관 레이어를 분리하거나 안정적인 y-sort가 가능해야 한다.

11. 어두운 숲 가장자리 나무
    - 화면 가장자리의 깊이를 만드는 진한 초록 변주.
    - 밝은 나무와 같은 픽셀 굵기와 비례.

12. 사과나무
    - 일반 나무와 같은 가족이지만 읽기 쉬운 붉은 사과가 소량 보이는 형태.
    - 기존 나무 위에 큰 빨간 사각형을 덧그리는 방식 금지.

13. 울타리·기둥·출입구
    - 밝은 꿀빛 목재.
    - 가로, 세로, 모서리, 끝기둥, 열린 1–2타일 출입구.
    - 기존 어두운 farm atlas 울타리와 다른 최종 시안 전용 패밀리.

14. 작물
    - 금빛 밀.
    - 주황 당근.
    - 밝은 양배추·잎채소.
    - 초록 옥수수.
    - 시안처럼 한눈에 종류가 읽히되 한 작물이 캐릭터만큼 커지지 않게 제작.

15. 꽃 군락
    - 흰 데이지, 복숭아·분홍 꽃, 노랑 들꽃, 소량의 보라 꽃.
    - 한 송이 단위의 큰 스프라이트보다 2–6송이의 낮고 작은 군락 변형.
    - 각 군락은 대략 6–24 world px 범위에서 읽히게 하고, 기존 30×30px 단일 꽃처럼 과대 표시하지 않는다.
    - 색상별 3개 이상의 배치 변주.

16. 물가·생활 소품
    - 갈대, 작은 강돌, 낮은 풀.
    - 과수원 벤치.
    - 표지판, 통, 작은 상자, 물뿌리개와 농장 수레 등 시안에 실제로 보이는 소품.
    - 소품 수는 시안의 밀도를 넘지 않고 길과 소리 접근 공간을 비워야 한다.

모든 생성 프롬프트에 다음 공통 조건을 반복해줘:

- 최종 시안 이미지가 팔레트, 픽셀 굵기, 실루엣, 재료와 명암의 기준이다.
- 2D 탑다운 3/4 RPG 픽셀아트.
- 32px 논리 격자와 기존 캐릭터 비례에 맞는 런타임 크기.
- 굵고 선명한 사각 픽셀 덩어리, 제한된 3–5단계 명암.
- 좌상단 광원과 짧은 우하단 접촉 그림자.
- 투명 오브젝트는 실제 알파 배경.
- 안티앨리어싱, 부드러운 그림, 3D 렌더, 아이소메트릭, 흰 배경, HUD, 캐릭터, 소리 구슬, 텍스트와 워터마크 금지.
- 건물·소품 하나를 요청할 때 불필요한 전체 풍경을 함께 생성하지 않기.

생성 원본은 그대로 보존해줘. 자르기, 투명 배경 정리, 팔레트 정리, nearest-neighbor 리사이즈와 타일 분해가 필요하면 비파괴 파생본으로 만들고 모든 처리 과정을 manifest에 기록해줘. 생성 결과를 bilinear로 줄이거나 오브젝트마다 서로 다른 비정수 배율을 적용하지 마라.

ImageGen이 타일 경계나 반복성을 정확히 만들지 못한 부분은 생성 결과의 아트 방향을 유지한 채 코드 또는 픽셀 편집으로 연결부를 정리해도 된다. 그러나 기존 에셋으로 되돌아가거나 큰 단색 도형을 최종 아트로 남기는 fallback은 금지한다.

## 5. 최종 시안과 동일한 공간 비율로 맵 재구성

현재 `lib/natureFarmLayout.mjs`의 기능적 모델을 보존 대상으로 삼되, 현재 좌표를 시각적으로 승인된 좌표라고 가정하지 마라. 최종 시안과 오버레이 비교해 주요 오브젝트의 중심, 크기, 길 폭, 개울 폭과 빈 공간 비율을 다시 맞춰줘.

확정할 공간 관계:

- 48×36타일, 1536×1152 world px 규격 유지.
- 최종 시안의 HUD 영역을 제외한 실제 맵 부분을 48×36 world grid에 정규화해 landmark guide를 만든다.
- S자 개울은 북쪽 중앙에서 들어와 가운데에서 완만하게 왼쪽·오른쪽으로 굽고 남동쪽으로 빠져나간다.
- 개울은 현재 구현처럼 일정 폭의 계단식 파란 띠로 보이지 않게 한다. 중심선은 타일 격자에 맞추되 시각적 둔치가 곡선과 돌·갈대로 분절되어야 한다.
- 정확히 두 다리만 유지한다. 위쪽 다리는 북쪽 생활 구역 아래, 아래쪽 다리는 남쪽 입구 위에 놓는다.
- 위쪽 다리, 아래쪽 다리, 물레방앗간, 북동 주택·온실, 세 개의 서쪽 밭, 동쪽 과수원, 남서 오두막의 상대 위치를 시안과 일치시킨다.
- 서쪽 밀밭이 현재처럼 지나치게 큰 정사각형이 되지 않도록 시안의 면적 비율을 맞춘다.
- 밭마다 크기와 작물 배열이 다르게 보이고, 밝은 울타리와 열린 출입구가 있어야 한다.
- 과수원은 시안처럼 열린 직사각형 울타리와 6그루 정도의 둥근 사과나무, 아래쪽 벤치로 읽혀야 한다.
- 북동 온실은 주택보다 약간 낮고 넓게 보이고, 집과 온실 사이에 꽃과 통행 여백이 있어야 한다.
- 남쪽 입구와 캐릭터 스폰 주변에는 넓은 모래길과 숲 사이의 열린 통로를 둔다.
- 길은 시안처럼 약 2–3타일의 유효 폭을 유지하되, 교차부가 거대한 모래색 사각 광장으로 퍼지지 않게 한다.
- 숲은 화면 가장자리에서 밀도가 높고 내부로 들어오며 성기게 풀린다. 현재처럼 같은 크기의 작은 나무가 일정 간격으로 놓인 테두리가 되지 않게 한다.
- 꽃과 돌은 시안의 군락 리듬을 따라 배치하되 주요 길·다리·문 앞·소리 후보 주변은 비운다.

시안의 캐릭터, HUD, D-pad, 소리 구슬은 위치와 규모를 이해하기 위한 참고다. 배경에 굽지 말고 기존 동적 레이어를 사용한다.

시안과 맵 좌표를 연결하는 landmark guide 또는 config를 코드나 디자인 문서로 남겨줘. 주요 랜드마크마다 다음을 기록해줘:

- 시안에서의 정규화된 bounding box.
- 48×36맵의 목표 좌표와 footprint.
- 실제 렌더 bounding box.
- 시안과 달라진 경우 그 이유.

주요 랜드마크의 중심 위치는 가능하면 시안 환산 좌표에서 1타일 이내, 보이는 폭·높이는 약 10–15% 이내로 맞춰줘. 충돌·문 접근 때문에 그 범위를 벗어나면 임의로 진행하지 말고 차이와 이유를 기록해줘.

## 6. 렌더링과 레이어 구조

새 환경 렌더링은 다음 순서를 명확히 유지해줘:

1. 잔디 기본과 낮은 지면 변주.
2. 길, 밭 흙과 개울 수면.
3. 강둑, 돌, 낮은 갈대와 지형 경계.
4. 다리 바닥, 울타리, 작물과 낮은 소품.
5. 건물 하부, 나무 몸통과 과수원.
6. 낮은 꽃·풀 군락.
7. 동적 소리 구슬과 캐릭터.
8. 캐릭터 발 위치에 따라 가려지는 지붕·수관·높은 갈대·다리 난간.
9. HUD, D-pad와 모달.

정적 지면과 소품은 오프스크린 canvas 또는 동등한 방식으로 프리렌더할 수 있다. 매 프레임 전체 맵을 다시 생성하지 마라. 동적인 수면 반짝임이나 식생 움직임은 제한된 지점에만 적용하고 소리 구슬보다 강하게 움직이거나 빛나지 않게 한다.

현재 렌더러처럼 지붕·수관의 위쪽 일부를 별도 foreground canvas에 무조건 한 장으로 덮는 방식이 캐릭터를 부자연스럽게 가리면, 오브젝트별 baseY 정렬 또는 구역별 전경 레이어로 개선해줘. 캐릭터 발과 소리 아이템이 완전히 가려지는 상황은 없어야 한다.

지형 색상은 코드의 임의 hex 값만으로 눈대중 결정하지 말고 최종 시안에서 주요 팔레트를 추출해 asset manifest에 기록해줘. 다음 재료군을 분리한다:

- 잔디 기본·밝음·그림자.
- 모래길 기본·하이라이트·접촉 경계.
- 물 기본·얕은 물·반짝임·깊은 면.
- 밝은 목재·중간 목재·어두운 접점.
- 크림 회벽과 청회색·적갈색 지붕.
- 꽃의 흰색·분홍·노랑·보라 포인트.

전체 화면에 필터를 덮어 팔레트를 맞추지 마라. 각 에셋의 재료색이 같은 팔레트 체계 안에서 직접 맞아야 한다.

- 꽃·소품 예약 영역과 소리 아이템의 겹침 없음.
- 새 Nature 렌더러가 금지된 기존 환경 에셋 경로를 참조하지 않음.
- 새 런타임 에셋 파일 존재와 이미지 로딩 성공.
- 정적 지형이 매 프레임 다시 생성되지 않음.

브라우저 검증:

- `/nature-test`의 배경 전용 조감과 위치별 검토.
- 실제 `/?natureQa=1` 또는 안전한 개발 경로에서 WorldMap → Nature → 소리 선택 → AnnotationPanel → 취소 → WorldMap 복귀.
- 위쪽·아래쪽 다리 양방향 통과.
- 건물·나무·밭·울타리·강둑·난간 모서리 충돌.
- 대각 이동과 큰 dt에서 터널링 없음.
- 데스크톱 1440×900.
- 모바일 세로 390×844.
- 모바일 가로 844×390.
- HUD, D-pad, 소리 안내, 카메라 끝과 전경 가림 확인.
- 브라우저 콘솔 오류, 이미지 404, 투명 배경 halo, 흐림, 타일 seam과 카메라 떨림 확인.

관련 Nature 파일 ESLint와 production build를 실행해줘. 기본 빌드가 환경 문제로 멈추면 원인을 기록하고 검증 가능한 지원 빌드를 실행하되, 성공한 다른 명령으로 원래 문제를 숨기지 마라. 전체 저장소의 기존 오류와 이번 변경 오류를 구분해줘.

외부 전사 데이터를 제출하지 마라. 실제 참가자 DB, Supabase 스키마, 배포와 push는 이번 작업 범위 밖이다.

## 10. 작업 범위와 최종 보고

현재 워킹 트리에는 Nature 구현 외에도 다른 마을과 기능의 미커밋 변경이 있다. 관련 없는 파일을 정리하거나 삭제하지 말고, reset·checkout·stash로 사용자 작업을 되돌리지 마라. 기존 Nature 기능 구현도 통째로 revert하지 말고 시각 렌더링과 필요한 좌표·충돌만 안전하게 개선해줘.

로컬 에셋 생성·편집, 코드 수정과 비파괴 검증은 진행해도 된다. 유료 에셋 구매, 외부 서비스 쓰기, 운영 데이터 변경, push와 배포는 별도 승인 없이 하지 마라.

분석이나 프롬프트 작성만 하고 끝내지 말고 새 환경 에셋 제작, 런타임 파생본 정리, 맵 재구성, 제품 연결 유지와 검증까지 완료해줘.

최종 보고에는 다음을 포함해줘:

1. 왜 기존 구현이 최종 시안과 달랐는지에 대한 짧은 진단.
2. 새로 생성·편집한 모든 에셋 목록.
3. 각 에셋의 생성 원본, 최종 런타임 파일과 프롬프트 경로.
4. 기존 환경 에셋 의존이 Nature 렌더러에서 제거되었다는 확인.
5. 최종 시안, 기존 구현, 새 구현의 동일 비율 비교 이미지.
6. 동적 요소 없는 전체 조감과 실제 플레이 줌의 주요 위치 캡처.
7. 레이아웃·에셋·충돌 관련 변경 파일.
8. 두 다리 순환, 충돌, A/B·전체 사운드, 블록 진행과 반응형 테스트 결과.
9. lint·build·자동 검증 명령과 결과.
10. 시안과 아직 다른 부분, 그 이유와 추가 개선 방법.
11. 로컬 확인 URL과 검토 순서.

완료 조건을 충족하지 못한 상태에서 “완전히 똑같이 적용했다”거나 “완료했다”고 표현하지 마라. 기능이 유지되고 시각 비교에서도 같은 ‘꽃피는 개울 농장’으로 명확히 인식될 때 완료로 보고해줘.

최종 목표는 기존 에셋으로 농장 요소를 나열한 맵이 아니라, ImageGen으로 확정한 밝은 잔디, 굽이치는 청록 개울, 두 목교, 따뜻한 농장 건물, 풍성한 둥근 나무, 작은 꽃 군락과 유기적인 길을 **하나의 통일된 전용 에셋 세트로 재현한 실제 플레이 가능한 SoundVillage Nature 마을**이다.
