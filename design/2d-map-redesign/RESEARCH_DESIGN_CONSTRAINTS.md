# Sound Village 2D 맵 리디자인 — 연구·설계 제약

작성일: 2026-08-28  
단계: 1단계 공통 디자인 바이블  
문서 성격: 리디자인 전 과정에서 지켜야 할 연구 프로토콜과 제품 제약의 기준 문서

범위 분류는 `SCOPE_AND_CONTEXT_FREEZE.md`를 우선한다. canonical key, unique constraint, RPC, migration, annotation 수정·legacy 처리·보상 재시도 정책은 연구 불변 조건이 아니라 **향후 기술 안정화 제안**이다.

## 1. 목적과 판정 언어

Sound Village는 일반적인 탐험 게임이 아니라, 여섯 소리 범주의 annotation 참여를 고르게 유도하기 위해 gamification을 사용하는 HCI 연구 도구다. 맵의 아름다움이나 게임성은 annotation의 정확성, 연구 타당성, 집단 분리, 마을 선택의 균형보다 우선할 수 없다.

이 문서는 다음 네 상태를 구분한다.

| 상태 | 의미 |
|---|---|
| 구현 확인됨 | 현재 코드·데이터에서 실제 동작을 확인함 |
| 문서 설명과 불일치 | 연구 목표 또는 승인된 설명과 현재 구현이 다름 |
| 아직 구현되지 않음 | 제품 의도는 있으나 현재 데이터·코드 경로에는 없음 |
| 추가 연구자 결정 필요 | 디자인 팀이 임의로 결정하면 연구 프로토콜이 바뀔 수 있음 |

## 2. 연구 목적 모델

기본 참여 루프는 다음과 같다.

`소리 청취 → 표현 annotation → 마을별 재화/재료 획득 → 여러 마을 재화 조합 → 집꾸미기 물품 구매`

이 구조가 유도하려는 행동은 한 마을의 반복 소비가 아니라 여섯 마을의 균형 있는 annotation이다. 따라서 다음 세 조건이 동시에 성립해야 한다.

1. 각 마을은 시각적으로 구분되지만 선택 매력은 과도하게 차이 나지 않아야 한다.
2. 재화는 마을별로 명확히 구분되고, 집꾸미기 구매에는 복수 마을 재화가 필요해야 한다.
3. 보상 연출은 annotation의 신중한 청취와 표현 작성을 방해하거나 답을 암시하지 않아야 한다.

## 3. 변경 불가 연구 규칙

다음 항목은 디자인 편의를 위해 바꿀 수 없는 연구 잠금 조건이다. 변경이 필요하면 구현 전에 연구자 승인을 받아야 한다.

### 3.1 Music-first 잠금

- 일반 참여자는 최초에 **Music 마을만** 접근할 수 있어야 한다.
- Music의 Block 1에서 자신의 연구 그룹에 배정된 모든 소리에 대해 유효한 annotation을 완료한 뒤 다른 다섯 마을이 열린다.
- 자신의 그룹에 배정된 Music Block 1의 15개 sound 모두에 유효한 annotation을 제출해야 하며 개별 sound skip 경로는 제공하지 않는다.
- 연구용 access ID는 검수 목적의 우회 경로이며 일반 참여자 흐름의 증거로 사용하면 안 된다.

현재 확인:

- `app/page.js`의 `FIRST_ZONE = 'Music'`과 초기 잠금 상태에서 구현 확인됨.
- 현재 해금 판정은 Music Block 1의 그룹별 소리를 조회하고 비-skip annotation 존재 여부를 확인한다. 확정 프로토콜은 “배정된 15개 모두 유효한 annotation 제출 완료”이며 skip 개념을 사용하지 않는다.
- 데이터상 Music Block 1은 전체 30개이며 A/B 그룹에 각각 15개가 배정되어 있다. 후속 구현 검수에서는 이 수량을 자동 테스트로 고정한다.

디자인 제약:

- 월드맵에서 Music은 “첫 목적지”임이 명확해야 하지만, 장기적으로 가장 보상이 큰 마을처럼 보이면 안 된다.
- 잠긴 마을은 정체성과 향후 목적지는 읽히되, 지금 즉시 입장 가능한 것으로 오인되면 안 된다.
- 해금 연출은 다음 마을 선택을 특정 방향으로 밀지 않고 다섯 마을을 동등하게 제시해야 한다.

### 3.2 박물관 그룹 분리와 진입 기준

승인된 연구 규칙:

- 참여자는 자신과 반대 그룹의 소리를 평가한다.
- 한 `sound_id`에 대해 **서로 다른 `participant_id` 5명의 유효 annotation**이 누적된 뒤 박물관 평가 대상으로 진입한다.
- 동일 참여자가 같은 `sound_id`에 남긴 중복 annotation 행은 후보 수를 늘리지 않는다.
- 한 참여자는 해당 sound의 후보 표현 하나만 기여하며, Museum은 이렇게 확정된 5명의 후보 표현을 사용한다.
- 후보 선정 자체는 무작위 추출하지 않고, Museum에 표시하는 5개 표현의 순서만 무작위화한다.
- 반대 그룹 조건은 metadata 배정뿐 아니라 후보 annotation 조회 단계에서도 명시적으로 검증해야 한다.
- 이미 평가한 소리는 같은 참여자에게 다시 제시하지 않는다.

현재 코드 대조:

| 항목 | 상태 | 확인 내용 |
|---|---|---|
| 반대 그룹 소리 선택 | 구현 확인됨 | A 참여자는 B 메타데이터, B 참여자는 A 메타데이터를 사용한다. |
| 이미 평가한 소리 제외 | 구현 확인됨 | 참여자별 기존 vote의 sound ID를 후보에서 제외한다. |
| 후보 누적 임계값 | **문서 설명과 불일치** | `MUSEUM_MIN_ANNOTATIONS`가 현재 4다. 코드 주석에는 P/Q 그룹 공석 때문에 5에서 4로 낮췄다고 기록되어 있다. |
| 후보 수 집계 | **문서 설명과 불일치** | 현재는 비어 있지 않은 annotation 행을 세며 고유 `participant_id`를 세지 않는다. 동일 참여자의 중복 행이 후보 수를 늘릴 수 있다. |
| 참여자별 후보 표현 | **문서 설명과 불일치** | 현재 조회는 동일 참여자의 중복 기여를 명시적으로 제거하지 않는다. 연구 기준은 참여자당 하나다. |
| 평가 표현 조회·순서 | 부분 구현 확인됨 | sound ID 기준 최대 5행을 가져와 클라이언트에서 표시 순서를 섞는다. 연구 기준은 고유 참여자 5명의 표현을 확정한 뒤 표시 순서만 무작위화하는 것이다. |
| 후보 행의 명시적 group 필터 | 아직 구현되지 않음 | 메타데이터 sound ID를 통한 간접 분리는 있으나 annotation 조회 자체에는 group/session 조건이 없다. 후속 구현에서 명시적으로 검증해야 한다. |
| 후보가 없는 박물관 | 구현 확인됨 | 입장은 가능하고 평가 카드에는 이용 가능한 소리가 없다고 표시된다. |

**판정:** 승인된 연구 기준은 sound당 고유 참여자 5명, 참여자당 후보 표현 하나, 확정된 5개 표현의 표시 순서만 무작위화하는 것이다. 현재 구현의 임계값 4와 annotation 행 개수 기준 집계는 이 목표와 불일치하므로 “준수”로 기록하지 않는다. 반대 그룹의 조회 단계 검증을 포함해 후속 구현 요구사항으로 남기며, 이 1단계에서는 코드를 변경하지 않는다.

### 3.3 annotation 유효성

- 최소 한 번 오디오를 재생하고, 공백이 아닌 표현을 입력해야 Stage 1 저장이 가능하다.
- confidence는 현재 1/3/5 값으로 저장된다.
- 확정 프로토콜에서는 `Skip`, `건너뛰기`, skip reason을 제공하지 않으며 skip row를 저장하지 않는다.
- 현재 코드에는 skip 기능과 `is_skipped=true` 행 저장 로직이 남아 있어 확정 프로토콜과 불일치한다. 이번 문서 단계에서는 코드나 legacy 데이터를 변경하지 않는다.
- annotation 창을 닫고 나중에 돌아오는 것은 허용할 수 있으나 annotation·진행률·보상은 저장되지 않고 sound는 미완료로 유지된다.
- 오디오 로딩 실패, 파일 누락, 네트워크 오류는 `technical failure`이며 annotation이나 skip row로 저장하지 않는다. 진행률·보상·해금·Museum 집계에도 반영하지 않고 재시도, 맵 복귀, 연구자 문의 경로를 제공한다.
- 연구 참여 중단·철회는 개별 sound skip과 분리된 연구 절차로 취급한다.
- annotation 저장 성공 후 재화 지급은 비동기이며, 보상 오류가 annotation 저장을 되돌리지 않는다.
- 시각·보상 요소는 특정 표현, 감정, 출처 또는 정답을 암시해서는 안 된다.

### 3.4 향후 기술 안정화 제안 — 중복 방지

이 절의 내용은 유용한 감사 결과이지만 이번 디자인 단계의 승인 조건이나 확정 구현 요구가 아니다.

- 동일 참여자가 서로 다른 sound에 제출하는 것은 정상이다. 향후 안정화에서 검토할 위험은 동일 `participant_id + sound_id + 연구 단계/세션 범위`에 둘 이상의 유효 annotation row가 존재하는 경우다.
- 이 범위에는 하나의 canonical valid annotation만 존재해야 한다. 연구 단계나 세션별 재평가가 필요하면 고유키 범위를 구현 전에 명시한다.
- 저장 중 UI 비활성화, 완료 sound 재제출 차단, 서버 멱등 처리, DB 고유 제약 또는 동등한 보호 장치를 함께 사용한다.
- 첫 유효 제출 이후의 중복 요청은 기존 성공 결과를 반환하되 새 row, 진행률, 재화, Museum 인원수를 만들지 않는다.
- 수정 기능이 필요 없다면 첫 유효 제출을 확정본으로 유지한다. 수정이 필요하면 새 행 추가가 아닌 감사 가능한 갱신 정책을 연구자가 별도로 승인한다.

### 3.5 데이터 및 진행 구조 보존

- annotation 저장, 블록 진행, 세션·참여자·그룹 식별, Supabase 테이블 구조는 시각 리디자인을 이유로 변경하지 않는다.
- 여섯 zone 식별자 `Animal`, `Human`, `Nature`, `Urban`, `Music`, `Lab`를 유지한다.
- 소리 메타데이터의 zone/group/block 배정을 디자인 편의를 위해 재분배하지 않는다.
- 전체 진행률은 현재 여섯 마을 진행률의 동일 가중 평균이다. 마을 크기나 시각적 중요도가 진행 가중치를 바꾸면 안 된다.

### 3.6 연구용 전체 접근 모드

| 접근 유형 | 현재 동작 | 검수 용도 |
|---|---|---|
| 일반 참여자 | Music만 열린 상태에서 시작하고 자신의 group sound만 사용 | 실제 연구 참여 흐름 |
| group-scoped 연구 ID | A 또는 B 그룹을 고정한 채 여섯 마을 잠금을 우회 | 실제 그룹과 같은 sound·배치 검수 |
| global 연구 ID | group 필터를 우회하고 여섯 마을에 접근 | 전체 콘텐츠 점검 전용 |

연구용 전체 접근 모드는 **구현 확인됨**이다. 다만 global 모드는 일반 참여자와 sound 구성 및 배치가 달라질 수 있으므로 이동 거리, marker 밀도, 해금 경험의 최종 승인 근거로 단독 사용하지 않는다. 시각 리디자인은 이 우회 기능을 제거하거나 일반 사용자에게 노출하지 않는다.

## 4. 마을별 재화와 집꾸미기 의도

승인된 제품 의도:

- 여섯 마을의 재화 또는 제작 재료를 통합하지 않는다.
- 각 재화는 색만 다른 동전이 아니라 실루엣·명칭·아이콘·텍스트 라벨로 구분한다.
- 집꾸미기 물품은 둘 이상의 마을 재화를 조합하는 recipe 방식으로 구매하게 한다.
- 특정 마을 재화가 거의 모든 인기 물품의 병목이 되지 않게 recipe 수요를 균형화한다.

현재 구현 대조:

| 항목 | 상태 | 확인 내용 |
|---|---|---|
| annotation 기본 보상 | 구현 확인됨 | annotation 5, vote 2의 단일 수치형 currency 보상이다. |
| 마을별 잔액 | 아직 구현되지 않음 | `participant_currency.balance` 단일 잔액을 사용한다. |
| zone별 보상 출처 | 아직 구현되지 않음 | annotation 보상 호출에 zone이 전달되지 않는다. |
| 집꾸미기 복수 재화 recipe | 아직 구현되지 않음 | house/interior catalog는 단일 `price`를 사용한다. |
| 의상 상점 복수 재화 | 아직 구현되지 않음 | shop catalog도 단일 `price`를 사용한다. |
| 재료 스키마 흔적 | 부분 확인됨 | daily quest SQL에 material zone/count가 있으나 주석상 미구현이며 현재는 currency fallback이다. |

**판정:** 마을별 재화와 복수 재화 구매는 연구·제품 의도로 디자인 바이블에 정의하되, 현재 기능으로 표현하거나 구현 완료로 주장하지 않는다. 실제 보상 구조 변경은 별도 승인, 데이터 마이그레이션, 연구 검토가 필요한 후속 기능 작업이다.

## 5. 디자인으로 조정 가능한 범위

연구 잠금을 유지하는 한 다음 요소는 조정할 수 있다.

- 타일·건물·식생·소품의 화풍과 팔레트
- 랜드마크 형태와 마을 실루엣
- 통로 폭, 광장 형태, 입구의 시각적 안내
- 활성 소리 발견 지점의 공통 시각 언어
- 재화 획득 연출의 위치, 지속 시간, 축약 방식
- 계절 오버레이와 이벤트 장식
- 전경 레이어, 조명, 안개, 물·입자 효과
- 미니맵·범례·상태 라벨의 시각 체계

다만 조정 결과는 이 문서와 `MAP_REVIEW_SCORECARD.md`의 연구 안전성 게이트를 통과해야 한다.

## 6. 선택 편향과 annotation 품질 위험

| 위험 | 관찰 가능한 징후 | 디자인 통제 |
|---|---|---|
| 마을 선택 편향 | 특정 마을 진입률·체류 시간이 지속적으로 높음 | 랜드마크 규모, 채도, 애니메이션 수, 보상 팝업 강도를 동급으로 맞춘다. |
| 이동 비용 편향 | 어떤 마을의 활성 소리까지 도달 시간이 더 김 | 입구→첫 활성 소리와 활성 소리 간 보행 거리의 중앙값을 비교한다. |
| 화면 과밀 | 활성 지점과 장식이 겹쳐 목표를 찾기 어려움 | 한 화면 활성 지점 수와 움직이는 장식 수에 상한을 둔다. |
| 보상 선점 효과 | 입력보다 재화 애니메이션에 시선이 먼저 감 | 보상은 저장 성공 뒤 짧게 표시하고 annotation 패널 위를 가리지 않는다. |
| 의미 프라이밍 | 배경 그림이 소리의 원천·감정을 암시함 | 소리 지점 주변에는 정답처럼 읽히는 구체적 원천 묘사를 피한다. |
| 피로와 성급 응답 | 이동·클릭이 길어 재생 횟수와 표현 길이가 감소 | 충돌 없는 짧은 접근, 명확한 상호작용 범위, 복귀 동선을 제공한다. |
| 색각·모바일 오인 | 재화나 상태를 색만으로 구분 | 실루엣, 패턴, 라벨을 항상 함께 사용한다. |
| 연구자 우회 경로 오검수 | access ID 화면만 보고 일반 흐름을 승인 | 일반 A, 일반 B, 그룹 연구 ID, global 연구 ID를 별도 시나리오로 검수한다. |

## 7. 균형 평가 지표

리디자인 전후에 가능한 한 같은 모집·기기 조건으로 아래 지표를 비교한다.

### 참여 균형

- 마을별 진입 참여자 비율
- 마을별 최초 선택 비율(Music 강제 단계 이후)
- 마을별 유효 annotation 완료 수와 완료율
- 참여자별 여섯 마을 진행률의 표준편차
- 마을별 입구→첫 활성 소리 도달 시간 중앙값
- 활성 소리 1건 완료당 이동 시간과 총 체류 시간

### annotation 품질

- 소리당 재생 횟수와 listening time
- 표현의 비어 있지 않은 길이 분포와 중복 표현 비율
- technical failure, 미완료 상태 복귀, 참여 중단·철회 비율
- confidence 분포
- 저장 실패·이탈률
- Stage 2 vote 완료율과 후보 없음 비율

### 디자인 진단

아래의 3초 인식 기준을 포함한 디자인 수치는 연구적으로 검증된 결과가 아니라 provisional 1차 휴리스틱이며 pilot test 후 조정한다.

- 3초 노출 후 입구·주요 경로·활성 소리 지점 식별률
- 첫 상호작용까지의 오클릭 수
- 충돌로 인한 우회·막힘 횟수
- 재화 아이콘의 마을 식별 정확도
- 320×180 축소 화면 및 모바일 화면에서 목표 식별률

해석 시 시각 리디자인 외에 모집 집단, 소리 난이도, 기기, 세션 길이가 달라졌는지 함께 기록한다. 디자인 효과라고 단정하려면 실험 조건과 분석 계획을 연구자가 승인해야 한다.

## 8. 구현 전 연구 안전성 게이트

다음 중 하나라도 실패하면 맵은 시각 점수와 관계없이 승인하지 않는다.

- [ ] 일반 참여자의 Music-first 잠금과 그룹별 Block 1 완료 해금이 유지된다.
- [ ] voluntary skip UI·저장 경로·상태가 없고 Music Block 1의 배정 sound 15개 모두 유효 제출되어야 해금된다.
- [ ] technical failure는 annotation·진행률·보상·해금·Museum 집계에서 제외되고 재시도·복귀·문의 경로가 있다.
- [ ] 향후 기술 검토 항목인 중복 방지 설계가 이번 시각 작업의 승인 게이트로 잘못 사용되지 않았다.
- [ ] A/B 참여자가 반대 그룹 소리만 평가한다.
- [ ] 박물관 진입 임계값이 연구자가 승인한 값과 일치한다.
- [ ] 이미 평가한 sound가 같은 참여자에게 재제시되지 않는다.
- [ ] annotation 패널의 재생·표현 필수 조건과 저장 payload가 유지된다.
- [ ] 활성 소리 지점이 충돌·전경·장식에 가려지지 않는다.
- [ ] 재화 연출이 소리 의미를 암시하거나 입력을 가리지 않는다.
- [ ] 여섯 마을의 시각적 매력과 접근 비용이 비교 가능 범위다.
- [ ] 연구 access ID와 일반 참여자 흐름을 각각 검수했다.
- [ ] Supabase schema, block, metadata, zone/group 배정을 임의 변경하지 않았다.

## 10. 후속 구현 요구와 남은 연구자 결정

사용자 승인 변경의 향후 기능 범위:

1. Museum 임계값을 sound당 고유 `participant_id` 5명으로 맞춘다.
2. 동일 참여자의 같은 sound 중복 행을 제거하고 참여자당 후보 표현 하나만 사용한다.
3. 고유 참여자 5명의 후보를 확정한 뒤 Museum 표시 순서만 무작위화한다.
4. 반대 그룹 조건을 후보 annotation 조회 단계에서도 명시적으로 검증한다.
5. voluntary skip UI와 skip row 저장 경로를 별도 기능 패치에서 제거한다.

canonical key, unique constraint, RPC, annotation 수정, legacy 중복·skip 처리, group/session 격리, 보상 재시도 및 DB migration은 **향후 기술 안정화 제안**이다. 이번 디자인 단계의 필수 구현·승인 조건에서 제외하며 코드나 데이터를 변경하지 않는다. 남은 디자인·제품 결정은 여섯 재화의 실제 명칭·recipe 경제와 기능 적용 시점이다.
