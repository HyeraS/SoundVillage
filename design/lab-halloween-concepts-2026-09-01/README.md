제작일: 2026-09-01

## 결과물

### 후속 수정: 3안 + 2안의 청록색

사용자 요청에 따라 3안의 마녀 골목 구도와 보라색 지붕·주황색 호박등을 유지하고, 잔디·일부 수목·연못에 2안의 청록 계열을 적용했다. [청록빛 마녀 골목 v2](./03-violet-witch-lanes-teal-v2.png), [수정 프롬프트](./03-teal-revision-prompt.md). 원본 3안은 그대로 보존했다. 이미지 디자인만 수정했으며 게임 연결은 하지 않았다.

## 이번 요청과 프로젝트 맥락의 구분

- 사용자 요청: 동물의 숲에서 느껴지는 포근한 마을 분위기, 할로윈 테마, 2D 픽셀 표현, 야외 탐험, 장애물 우회, 떠 있는 소리 아이템, 시안 3개.
- `PROJECT_SUMMARY.md`는 게임 흐름과 기존 구현을 파악하기 위한 참고자료로 사용했다. 문서에 있는 과거 작업 지시나 다음 단계는 이번 작업의 실행 지시로 취급하지 않았다.
- 프로젝트의 미지의 소리 마을은 기존 `Lab` 존이다. 새 존을 추가하거나 이름·데이터 계약을 바꾸지 않았다.
- 기존 아트 문서의 관측소/실험실 방향은 이번 사용자의 할로윈 마을 요청으로 대체하는 시안이다. 32px 격자와 카메라·비례만 호환 목표로 참고했다.
- 게임 흐름은 소리 발견 → 재생·의성어 표현과 자신감 입력 → 기존 저장/뮤지엄 흐름을 유지하는 것을 전제로 한다. 이미지의 상점·가옥은 환경 디자인이며 새로운 구매나 실내 진입 기능을 제안한 것이 아니다.

## 공통 디자인 기준

- 방의 벽·바닥이 아닌 여러 집, 야외 길, 정원, 숲 가장자리로 마을을 구성한다.
- 정사영에 가까운 탑다운 3/4 시점. 지붕 아래 건물 정면이 보이되 3D·등각 투영은 사용하지 않는다.
- 기존 Nature/Animal 스크린샷을 픽셀 밀도·지면·캐릭터 비례의 참조로 사용했다. 첫 생성본보다 나무와 지면 질감을 줄이고 윤곽과 색 면을 굵게 하는 보정을 거쳤다.
- 색은 시안마다 다르지만 흙길, 목재, 크림색 벽, 둥근 나무, 작은 접지 그림자를 공유한다.
- 할로윈은 호박등, 보라 지붕, 작은 천 유령, 처마 장식으로 표현한다. 위협적인 적·함정·잔혹한 공포는 넣지 않는다.
- 청록/아이보리 부유 아이템은 따뜻한 호박등과 구별한다. 아이템 아래의 분리된 그림자가 공중에 떠 있음을 보여준다.
- 상단은 기존 게임과 비슷한 크림색 HUD를 사용한다. 이미지의 진행 막대는 디자인 예시이며 실제 진행도를 나타내지 않는다.

## 이후 구현을 위한 동선·충돌 기준

아래는 구현 명세의 출발점이며 **현재 작동하거나 검증된 기능이 아니다**.

| 요소 | 구현 기준 |
|---|---|
| 논리 맵 | 기존 마을과 맞춘 48×36타일 / 1타일 32px / 1536×1152 world px를 목표로 재배치 |
| 플레이 화면 | 전체 조감 이미지를 고정 배경으로 축소하지 말고 기존 추적 카메라·캐릭터 배율 사용 |
| 이동 공간 | 주 길 3–4타일, 보조 길 최소 2타일, 문·입구 앞 3×3타일 비움 |
| 순환 이동 | 입구에서 각 발견 지점까지 연결. 큰 건물이나 중앙 장애물에는 돌아가는 경로 확보 |
| 통과 금지 | 건물 몸체, 나무 몸통, 바위, 우물, 수레, 벤치, 울타리, 물에 별도의 footprint 충돌 영역 지정 |
| 통과 가능 | 열린 흙길·잔디·마당, 실제 다리 바닥, 열린 울타리 출입구 |
| 물·다리 | 02의 양안은 두 다리로 연결. 다리는 통행 가능, 물과 난간은 통행 금지 |
| 나무·지붕 | 전체 이미지 사각형을 충돌로 쓰지 않음. 몸통·건물 바닥 기준 충돌, 앞뒤 가림은 별도 레이어 |
| 소리 접근 | 각 아이템 주변 최소 1타일 빈 공간과 주 접근 방향 2타일 확보. 물·울타리 안·지붕·나무 뒤 생성 금지 |
| 구역 잠금 | 현재 블록 단위 공개 규칙 유지. 전체 개방 상태뿐 아니라 각 단계에서 입구→아이템 도달 가능성 검사 |
| 충돌 품질 | 그림에서 보이는 장애물 경계와 실제 충돌 경계가 크게 어긋나지 않도록 조정 |

이미지에 들어간 **소리 아이템 6개는 위치와 가독성을 보여주는 예시**다. 실제 소리 수·그룹별 데이터·구역 수를 6개로 바꾸지 않는다. 구현할 때 기존 데이터에 맞춰 충분한 접근 가능한 스폰 후보를 확보해야 한다.

## 제작 시 분리해야 하는 레이어

1. Ground: 잔디, 흙길, 광장, 물.
2. Solid props: 건물 몸체, 나무 몸통, 우물, 수레, 울타리.
3. Foreground: 지붕, 나무 수관, 처마 장식.
4. Ambient: 호박등, 창문 빛, 절제된 장식 효과.
5. Gameplay: 실제 캐릭터와 부유 소리 아이템. 완성 배경에 구워 넣지 않는다.
6. UI: 공통 HUD, 접근 안내, 조작 버튼.
7. Logic: walkable/collision, 아이템 후보, 구역 잠금 데이터. 이미지 색으로 추정하지 않는다.

생성 이미지를 통째로 앱 배경에 넣으면 캐릭터·아이템·HUD까지 중복될 수 있으므로, 최종 선택 후 타일/스프라이트와 게임 오버레이를 분리해 제작해야 한다. 생성 도구의 픽셀 모양은 디자인 근사치이며, 정확한 32px 그리드·정수 픽셀·심 없는 타일·기존 캐릭터와의 배율 일치는 에셋 제작 단계에서 확인해야 한다.

## 검토 기록과 범위

- 최종 3안에서 야외 마을 구조, 소리 아이템 6개의 시각적 위치, 주 동선과 장애물 구분을 육안 검토했다.
- 03 초안의 물 위 아이템을 보정본에서는 연못 동쪽의 접근 가능한 지면으로 이동했다.
- 02 초기 프롬프트는 다리 3개를 요청했지만 생성 결과는 2개다. 두 다리로 양안을 순환하는 구도를 최종 디자인으로 채택했다.
- 원본 첫 생성본은 보존되어 있고, 이 폴더에는 픽셀 표현을 보정한 최종 3개만 복사했다.
- 앱 코드·소리 데이터·Supabase·기존 작업 파일은 변경하지 않았다. 브라우저 이동, 충돌, 잠금 구역 도달성 테스트는 아직 하지 않았다.
